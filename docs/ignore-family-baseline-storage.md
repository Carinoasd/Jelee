# 合併基線分類保存

## 資料與提交

schema18 新增 `job_ignore_family_decisions`，保存缺失、排除、未知三態，以及排除來源種類、原因、行號和命中祖先。資料庫拒絕不合規則的來源關係：自有規則必須屬於命中路徑的嚴格祖先；舊格式可用目錄內來源排除該目錄；最終檔案不能冒充來源目錄。空來源與全無效來源行號為 0。

`BeginFamilyIgnoreBaselineComparison` 要求掃描完整、無略過、每個根都有兩種格式一致的目錄身份和獨立舊格式查詢。開始後凍結清單、目錄與合併排除資料。它保留既有不可比較舊範圍的處理，不把未知舊屬性硬算成缺失。`NextFamilyIgnoreBaselinePage` 沿用索引順序讀取 128 筆原始基線，只交出其中未觀察到的候選。

`CommitFamilyIgnoreBaselinePage` 必須完整提交待處理頁，不能省略、插入或重排候選。每筆結果使用領域層的共用證據驗證；非未知分類必須有完整自有祖先鏈或首個確認缺失邊界。排除來源需對應保留的規則證據。最後既存父目錄也必須已完成枚舉且沒有略過。

## 原子性與重播

分類、來源、計數和收據在同一交易提交。同頁共用的自有目錄與舊格式查詢先去重，前者按父先子後保存，後者最多 128 個查詢一批。兩種格式共用外層 savepoint；任何來源衝突都回滾本頁新證據，只保留兩份來源清單失效標記。還會集合比對前頁或掃描已保存的兩種目錄身份與缺失邊界，拒絕同時宣稱缺失和存在。

新摘要版本包含頁 token、分類全部欄位、來源種類、證據數量、完整規則 proof、原始查詢與缺失邊界。相同收據可重播而不重複計數，變更任何證據的重播會被拒絕。EOF 要求實際處理總數等於固定基線總數。提交前再次檢查基線版本、租約及清單世代；晚到的租約過期會回滾來源與分類。

舊模式入口仍拒絕合併模式，公開模式驗證沒有放寬。已有 001–017 遷移未修改。降回 17 時若保留合併比對資料就拒絕，刪除任務歷史可正常串聯清除。

## 驗證與範圍

- 真實 PostgreSQL race 專項 8 項通過、零失敗、零略過，26.680 秒。涵蓋 130 筆跨頁、三態計數、截斷拒絕、完整重播、變更證據拒絕、EOF、實際寫入後的跨格式回滾、既有缺失／存在矛盾、取消、世代變更及提交中租約過期。
- 真實檔案系統、受限規則子程序到 PostgreSQL 分類保存：1 項通過、零略過，17.318 秒，6 筆基線得到 1 筆已觀察、1 筆缺失、4 筆排除。包含空來源、全無效來源、自有排除及缺失父目錄；完成後無存活子程序。
- Windows domain/scan/architecture 全套及全專案 vet、三命令 build 通過；Linux 原生檔案系統 race 三套通過。

本段尚未串接合併模式的最終發布、正式 worker 或公開 API，G22 與第 3 階段仍未完成。

完整 PostgreSQL race 回歸：227 項頂層測試通過，零失敗、零略過，299.821 秒；測試期間 PostgreSQL 原始碼雜湊不變。證據保留於本機忽略目錄 `.testdata/inventory-family-baseline-full-postgres-summary.json`。外層測試觀察期限調為 600 秒，fixture、SQL 與租約期限保持原值。
