# NFO 演員結構

第32版新增 `actor-structure-v1`，固定22個欄位：已支援的九文字、四數值、八字串列表與 `actors`。已發布投影的欄位集合保持。

`facts[].field = actors` 的值是有順序的 JSON 物件陣列，以 PostgreSQL JSONB 保存。

| 欄位 | 契約 |
| --- | --- |
| name | 必填、非空白，最多1024個 UTF-8 位元組 |
| role | 可省略，最多1024個 UTF-8 位元組 |
| thumb | 可省略，最多4096個 UTF-8 位元組；保存參照不會下載 URL 或開啟檔案 |
| order | 可省略或 null；整數0–1000000。未提供與明確0保持區別 |

最多128位演員，所有演員字串合計最多16384個 UTF-8 位元組；拒絕 NUL、非法型別、未知 JSON 屬性及超限資料。保留原始排列與重複演員，不依 order 重新排序。同一個 `<actor>` 的 name／role／thumb／order 不得重複；確認套用拒絕歧義，而一般相容 parser 保持原行為。

Reader 的演員切片與 order 指標由呼叫者獨立持有。來源選擇、完整原始位元組與實體身分重核包含演員結構，保存仍走原有的 NFO-only／供應商融合交易。

人工省略 value 保留值；null 與空陣列均是明確清除，兩種表示保持。人工給值或清除移除 NFO 值與獨立鎖證明，只改 locked 保留證明。後續確認保留人工值與清除，仍可記錄新的正鎖。Actors／Actor／Cast 指定鎖沒有值時，不虛構 NFO 值來源與時間；新版全域鎖涵蓋22欄。

```json
{"expectedRevision":2,"facts":[{"field":"actors","value":[{"name":"演員甲","role":"主角","order":0},{"name":"演員乙"}]}]}
```

文字、列表與演員的最大合法混合請求在 JSON 轉義後可能超過1 MiB，管理修改上限調整為2 MiB。OpenAPI 宣告演員物件、欄位限制與人工清除。

第32版新增有界演員驗證函式，擴充既有 facts／來源／鎖約束。保留演員資料（包括人工清除）、演員鎖或新版投影證明時拒絕降版；沒有新版資料時，舊列表資料可往返32→31→32。001–031共62份已發布遷移保持原樣。

本段仍屬第三階段，未完成全案。多來源評分、ID、季集、實際匯入、前端與無損 NFO 回寫仍待接續。
