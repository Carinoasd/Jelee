# 舊基準來源觀察與最終重新觀察

## 舊基準分類

`Resolver.EvaluateBaseline` 與一般候選規則評估使用同一個有界規則流程，但允許明確確認祖先目錄缺失。它先讀取所有可達祖先規則；若在已開啟父目錄句柄下確認單一子目錄不存在，會停止深入，依已讀規則評估候選，並附上一筆 MissingDirectory 證明。

缺失證明包含子目錄相對路徑及父目錄身份，不包含自身身份或規則欄位。根不能被表示為缺失。權限錯誤、失效父句柄、連結或非目錄不會降級為缺失。

回傳前重新開啟並核對整條已觀察祖先鏈，再次確認該子目錄不存在。若它已出現，回傳來源改變錯誤並清除全部結果。觀察 token 包含明確缺失路徑與父身份，因此兩個不同缺失子目錄不會共用同一 token。一般 `Evaluate` 仍保留原先嚴格行為。

## 最終復核

`Resolver.ReobserveDirectory` 重新讀取指定目錄與祖先的身份、固定規則檔存在狀態和完整內容摘要，不以規則的排除結果跳過指定目錄。如此即使新規則排除曾觀察的後代，持久清單仍能核對該來源的變化。

它完整觀察兩次並逐欄比較；第一個明確缺失祖先會終止證明清單，不捏造其後代的缺失記錄。規則或目錄在兩次觀察之間改變時，結果清空。成功回傳仍是有界觀察，不能提供檔案系統原子快照；工作程序須將指定證明和持久清單逐項比較。

兩個入口沿用來源處理名額、共用期限、路徑深度和原文大小限制。回傳證明為獨立副本，不包含原文、絕對路徑或檔案句柄。

## 驗證與接續

Windows 來源套件與架構測試、來源套件 vet 通過。Linux 原生 /tmp 快照下 race 與 vet 通過，零跳過，來源套件覆蓋率86.8%。案例涵蓋缺失祖先、不同缺失路徑的 token、第二次觀察時目錄或規則出現、規則變動、不安全父類型、被排除後代的重新觀察、取消與名額限制。
