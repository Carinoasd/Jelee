# 確認 TMDB 候選後套用文字欄位

本頁保留該階段的實作與驗證；後續第24版的三態保存及可信缺失／損壞回退，見[最新回退契約](nfo-tmdb-fallback.md)。

管理員可呼叫 `POST /api/v1/items/{id}/metadata/tmdb`，提供 `resource`（movie／series）、正整數 `providerId`、目前 `expectedRevision` 與明確 `confirmed: true`。入口需要已配置 TMDB 金鑰；搜尋仍只回傳候選，套用需要另行確認。HTTP 不接受任意欄位值或來源網址。

應用先以短交易驗證管理員、項目種類、版本與媒體庫偏好，再於交易外取得電影／劇集詳細資料。最終交易重新核對有效 session、版本、種類及 NFO 設定；網路等待期間不持有資料庫項目鎖。版本變更回傳 409，不覆蓋等待期間的人工修改。

## 寫入規則

- 支援標題、原名、簡介、日期四欄。供應商缺值不清空現有資料。
- 鎖定欄位及人工來源均保留，包括人工明確清空的欄位。保護判斷位於最終寫入交易內。
- 原有非空欄位預設保留；既有標題只有明確 `replaceExistingTitle: true` 才可取代。人工與鎖定標題仍保護。
- 每個套用欄位保存 TMDB ID、資源類別、固定官方頁面、要求語言及取得時間。簡介回退時保存其自己的語言與取得時間，不冒充主回應來源。
- 人工接管會移除該欄的供應商來源；只改鎖保留既有值與來源。被略過的欄位不修改時間或來源。
- 目錄標題、欄位、版本及前後稽核在同交易更新。SQL 中途失敗全部回滾。
- 接受的確認即使全部欄位受保護，仍推進版本並記錄 applied／skipped。HomeVideo 接受至少一個電影欄位後改為 Movie；全部略過保持種類。

第 22 版遷移新增受約束的供應商來源欄位。非 TMDB 來源不可帶這些欄位，TMDB 必須提供完整且有效的來源。保留任何供應商來源時拒絕降版；全部人工接管並清除來源後可降回 21。原 001–021 遷移保持。

## 驗證與範圍

正式整合測試通過實際 HTTP、應用、受控 TLS 供應商及 PostgreSQL：100 部合成電影與 20 部合成劇集逐一按名稱與年份搜尋、比對候選、明確確認並核對四欄與目錄標題。這是合成匹配案例；原始媒體 inventory、worker 與影集階層匯入未包含在此矩陣。

另驗證 401／403、非法確認意圖、429 重試、非法上游回應、取消、簡介語言回退及查詢期間的人工修改。刻意停用領域的鎖定判斷時，正式 HTTP／TLS／PostgreSQL 測試因覆蓋鎖定欄位而失敗，隨後逐位元復原。SQL 約束與中途失敗測試使用實際資料庫。

完整執行數、來源雜湊、首次失敗及復驗紀錄見[證據](evidence/tmdb-metadata-apply.json)。
