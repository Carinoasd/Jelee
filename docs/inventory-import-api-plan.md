# 掃描候選匯入 API

在既有 jobs 的登入、管理員、請求容量與取消邊界內提供 `PUT /api/v1/jobs/{id}/entries/{entry}/item`。輸入只含標題、影片種類與可選父層 ID；來源位置由資料庫解析。

應用層先以有效管理員身分取得候選，接著在交易外核對檔案，最後以短交易重新檢查身分、候選與父層並提交。來源核對期間撤銷 session 或停權必須拒絕。所有路徑保持私有，錯誤沿用既有四語問題回應。

PUT 以來源位置唯一約束保證不重複建立項目；相同候選與相同標題／種類／父層已有條目時回傳既有 ID，不再稽核或改寫。若既有值不同則衝突，不把匯入當成更新人工資料的入口。重試仍須符合目前候選與檔案條件。

原有本機 CLI 保持重複位置拒絕。不新增 migration，不修改既有SQL。API OpenAPI 契約、真實 TLS／PG、未登入／非管理員、重試／衝突及來源核對期間撤權一併驗收。
