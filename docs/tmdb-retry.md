# TMDB 預檢的 HTTP 重試

已接入既有正式憑據啟動預檢，G14.3 僅部分完成。HTTP 429／5xx 最多嘗試三次（含第一次），總期限 15 秒並接受取消。Transport／SSRF／大小失敗、401／403、非法成功正文與重定向都直接失敗。

## 等待政策

未提供 Retry-After 時，兩次等待基準為 250／500 ms，各加入 0–25% 抖動。提供時接受非負十進位秒數或 HTTP-date，使用伺服器指定最低等待與退避值的較大者。[RFC 9110 §10.2.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.2.3)。

標頭最多解析 128 bytes；格式無效、整數溢位或等待超過剩餘期限時停止，以該回應的安全錯誤結束。超大合法等待不會截成较短時間後提早重試，也不會在期限外建立背景等待。timer會關閉並把取消／超時傳回呼叫者。

TMDB 官方要求尊重 429，服務限制可能調整，本實作沒有把歷史限額寫死成帳戶剩餘配額。[官方限流說明](https://developer.themoviedb.org/docs/rate-limiting)。憑據檢查不快取，每次啟動仍會向正式端點確認。

## 驗證

- Retry-After 秒數／日期／過去時間／零值、溢位／超長／非法值、退避界限、429及5xx恢復／耗尽、認證與安全失敗不重試、期限不足與等待取消通過。
- 真 TMDB 適配器經自有 TLS 服務，429後200且至少等待1秒；完整實際標頭從受控client傳到適配器。拿掉標頭傳遞後此case失敗，finally逐位元恢復，相關完整回歸通過。
- Windows 完整 Go 29 包，2,858 pass events（含父測試）、435 skip events；skip名稱集合逐項等於前段完整清單。完整vet通過；Linux四包race通過，摘要未列skip，沒有零略過宣稱。
