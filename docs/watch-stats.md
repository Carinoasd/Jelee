# 观看统计口径（G23.3）

本文定义 Jelee 观看统计的计算口径。实现位于 `internal/domain/watch_stats.go`（纯函数，无数据库依赖），单元测试 `internal/domain/watch_stats_test.go` 以边界用例表逐条覆盖本文规则。采集（G23.1）、批量写入（G23.2）、隐私（G23.4）与 SQL 汇总（G23.5）不在本文范围；SQL 汇总只对本文产出的“每日行”求和，不得另立口径。

## 输入

一次播放会话的上报样本，按服务端接收顺序排列。每个样本含：

| 字段 | 含义 |
| --- | --- |
| `At` | 服务端接收时间（墙钟） |
| `Kind` | `start`、`progress`、`pause`、`resume`、`seek`、`stop`、`fail` |
| `Position` | 事件后的媒体播放位置 |
| `Paused` | 仅 `progress`：客户端报告当前处于暂停 |
| `From` | 仅 `seek`：跳转前位置（客户端提供时） |

以及条目时长 `runtime`（未知时为 0）。

## 可配置参数与默认值

| 参数 | 默认 | 允许范围 | 作用 |
| --- | --- | --- | --- |
| `MaxReportGap` | 5 分钟 | 10 秒–1 小时 | 两次上报间隔超过此值时，只计入此值 |
| `MaxPlaybackRate` | 2.0 | 1–4 | 媒体前进量超过 `墙钟 × 倍率 + 容差` 视为跳转 |
| `PositionTolerance` | 3 秒 | 0–30 秒 | 位置抖动容差 |
| `CompletedRatio` | 0.9 | 0.5–1 | 覆盖率达到此值即“完成” |
| `MinViewDuration` | 2 分钟 | 0–30 分钟 | 计为一次观看的最低有效时长 |
| `MinViewRatio` | 0.1 | 0–1 | 短条目按时长比例降低门槛 |
| `MinResumePosition` | 30 秒 | 0–10 分钟 | 低于此位置不保留续播点 |

## 有效观看时长

逐一检查相邻两个有效样本之间的区间（前一个称“锚点”）：

1. **播放状态**：只有锚点处于播放状态的区间才可能计入。`start`、`resume`、未暂停的 `progress` 进入播放；`pause`、带 `Paused` 的 `progress` 进入暂停；`seek` 保持原状态；`stop`、`fail` 结束会话，其后样本全部忽略。因此暂停时间永不计入。
2. **时钟回拨**：后一样本时间早于锚点时，该区间不计，后一样本成为新锚点。
3. **Seek**：带 `From` 的 `seek`，区间只判定到 `From`（跳转前实际播放的部分），新锚点取跳转后的 `Position`；不带 `From` 时按普通区间判定。
4. **跳转**：媒体前进量小于 `-容差`（后退）或大于 `墙钟 × 倍率 + 容差`（快进、章节跳过）时，该区间不计。容差内的小幅后退不计且不算跳转。
5. **计入量**：`min(墙钟, 媒体前进量)`。卡顿或空转（墙钟大于前进量）只计前进量；倍速播放（前进量大于墙钟）只计墙钟，不虚增时长。
6. **上报间隔异常**：墙钟超过 `MaxReportGap` 时，计入量封顶为 `MaxReportGap`（多半已断连，只信任开头一段）。等于上限不封顶。
7. **重叠区段**：每个计入区间对应墙钟片段 `[锚点时间, 锚点时间 + 计入量)`，先求并集再求和。重复样本、时钟回拨造成的重叠不会重复计时。每日汇总时同一用户同一条目的多个会话（例如两台设备同时上报同一次观看）也按并集计。

格式错误的样本（时间为零、未知类型、负位置、负 `From`）被忽略并计入诊断计数，不影响其余计算。

## 覆盖率、完成率与续播点

- **覆盖**：计入区间对应的媒体区段 `[锚点位置, 锚点位置 + 前进量]` 的并集长度，裁剪到 `runtime`。规则 6 封顶时只取计入量长度。倒回重看会增加有效时长，但不增加覆盖。
- **完成率** = 覆盖 / `runtime`，上限 1；`runtime` 未知时为 0。
- **完成**：完成率 ≥ `CompletedRatio`。
- **计为观看**：已完成，或有效时长 ≥ 门槛。门槛 = `min(MinViewDuration, MinViewRatio × runtime)`；`runtime` 未知或 `MinViewRatio` 为 0 时门槛为 `MinViewDuration`。有效时长为 0 时永不计为观看。
- **续播点**：最后位置；以下情况为 0：会话已完成、最后位置 < `MinResumePosition`、最后位置 ≥ `runtime × CompletedRatio`。

## 首播与重看

按会话开始顺序对同一用户同一条目累积 `WatchHistory`（观看次数、完成次数、最近一次计数会话是否完成）：

| 情况 | 分类 | 观看次数 |
| --- | --- | --- |
| 未计为观看 | `none` | 不变 |
| 此前无任何观看 | `first`（首播） | +1 |
| 最近一次计数会话已完成 | `rewatch`（重看） | +1 |
| 其他（上次未看完，接着看） | `continue` | 不变 |

“观看次数”即首播数加重看数，分多次看完一部影片只算一次。

已知局限：两台设备同时上报同一次观看时，时长按并集去重，但分类逐会话进行，第二个会话可能被计为 `continue` 或 `rewatch`。采集层（G23.2）按会话 ID 去重可降低此情况。

## 每日汇总与周期

`AggregateWatchDaily` 按报告时区输出每日行（日期、用户、条目、库、类型、有效时长、计数会话数、观看次数、首播、重看、完成次数）：

- 有效时长在报告时区的午夜切分，跨日会话分别计入两天。
- 计数字段（会话、观看、首播、重看、完成）归入会话第一个计入片段所在日期；没有计入片段时归入第一个样本所在日期。
- 周、月、年、按库、按类型与 Top N 均为每日行之和。周期起点由 `WatchPeriodStart` 给出：日为当地午夜；周按 ISO 8601 从周一开始；月为 1 日；年为 1 月 1 日。

## 修改口径

参数可配，但规则本身改变时必须同步修改本文、`watch_stats.go` 文档注释与边界用例表，并说明已有历史数据是否需要重算。
