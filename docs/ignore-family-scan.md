# 自有與舊格式規則的合併掃描

## 組合政策

`.jeleeignore` 明確 Include 或 Exclude 時採用該結果；只有 Unmatched 才查 `.ignore`。這是 Jelee 的跨格式組合政策，並非從舊格式上游推定的優先順序。已排除父目錄不會因子目錄規則復活。自有規則使用指定的大小寫策略，舊格式仍依固定上游匹配語義。

## 掃描與證據

`FamilyIgnoreScanner.ScanFamilyIgnoreDirectory` 從原生持有的目錄枚舉候選，保留自有規則全鏈證據與最近舊來源查詢。未匹配檔案每批最多 128 個，共用一次匹配；目錄須查自身來源並核對候選身份及父鏈。Windows 在持有的父目錄下開啟候選取得身份，不以絕對路徑重新開啟。

每批核對兩種來源的完整目錄身份鏈；舊來源在批次間改變即失效。排除結果保存 family、reason、來源目錄、行號與命中路徑；空來源與全無效來源以行號 0 保留原因。中間批次都是暫存結果，Done 前重新核對目前目錄來源。子目錄查詢仍須在整個任務發布前重新驗證。

整次掃描最多同時兩個；枚舉與舊來源觀察使用不同 resolver，避免巢狀取用相同名額。共享 30 秒期限傳到匹配程序，取消不送出部分批次；呼叫端的更短期限優先。helper 另有既有程序數量、記憶體與執行期限限制。

## 驗證與範圍

- 真實 helper：明確自有包含／排除、舊規則排除、空檔、全無效來源、命中行與來源、Done、程序 Active 歸零。
- 原生目錄替換拒絕、來源在批次間變動拒絕、callback 錯誤保留。
- 兩次並行掃描皆可進入匹配，取消傳遞、期限傳遞及名額釋放。
- Linux CI 加入獨立非 race 真實 helper 測試；其餘邏輯仍跑 race。

目前只有掃描 adapter 與領域批次合同，schema 仍為 14。公開模式、組合證據的原子保存、基線分類、發布守衛與正式 worker／報告尚未接線；本段不代表 G22 或第 3 階段完成。
