## 迁移和品牌范围

采用需求已允许的渐进替换，新增 Go 入口不反向代理到旧服务。G02/G05 等功能裁剪可先在 Go 的可达 API 面成立，但相应 Go 功能、表、翻译、图标未完成前，各完整子项不能标为完成。

**2026-10-04 取代旧决定：工作树不再保留上游 C# 源码。** 原先“保留原 C# 源码作历史比对与回滚”的决定由本条取代，理由如下：

- 需求原文零.7 只要求保留许可证、版权声明、上游 Git 历史与法定归属，并未要求在工作树保留旧源码；G28.1 把 C#/.NET 定位为“迁移期参考或兼容旁路”，Go 服务从未反向代理或调用旧服务，也不读取旧树中的任何文件。
- G00 验收要求 `make brand-scan` 全仓零非白名单命中；白名单只能列明确文件，不能豁免整个旧树。旧树约 1.47 万处遗留命名不可能逐文件“协议必需”地白名单化，保留旧树与 G00 验收互相冲突。
- 旧树相关 CI（.NET 测试、格式、ABI 比较、CodeQL C#、OpenAPI 生成）只验证不再交付的程序，维持它们不提供 Jelee 的行为证据。

回滚与历史比对改用 Git：删除前最后一个含完整 C# 树的提交以标签 `upstream-csharp-final` 标记（由主线在合并时建立，指向本分支起点）。需要比对或恢复时用 `git show upstream-csharp-final:<路径>`、`git checkout upstream-csharp-final -- <路径>` 或 `git worktree add <目录> upstream-csharp-final`；原审计基线提交仍见 [审计基线](00-audit-baseline.md)。Go 端仍需要的四语 UI 字串已移到 `web/src/i18n/<locale>/core.json`，其余旧数据（国家、语言、分级表等）Go 端未使用，随树删除、可从标签取回。许可证义务的处理见 [许可证与来源](LICENSE-COMPLIANCE.md)。

根许可证、贡献名单与必要第三方 NOTICE 不改写。审计、原始需求、迁移说明里的旧品牌名称属于可解释来源引用。品牌扫描可以为这些**明确文件/原因**设法律与需求来源例外，不能把整个目录列为品牌通过白名单。新 Go 范围通过不能冒充全仓通过；移除旧树后完整扫描本身即为 G00.4 的验收依据。
