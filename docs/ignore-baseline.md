# 忽略规则的基线分类（schema 10）

## 持久分类合同

`BeginIgnoreBaselineComparison` 在有效任务租约下确认当前根范围、完整目录覆盖、零 skipped 和所有根的来源证明，随后保存基线版本和分类进度。比较开始后，数据库触发器冻结该任务的库存和目录；历史删除父任务仍可级联清理，库基线不依赖历史任务。

`NextIgnoreBaselinePage` 先按根 UUID 和 C 排序路径取得最多 128 条原始基线，再查找本轮已观察路径。全页均已观察时，返回空候选但仍有原始页计数；必须提交空分类推进游标，不能误认为 EOF。只有原始页为空才结束。

`CommitIgnoreBaselinePage` 要求分类精确对应下一页所有未观察项，顺序、数量、根和路径均须相同。缺失和排除分类需要保留的祖先来源链与已完成枚举证据；排除还要指向存在的规则来源。数据库缺一条记录不能证明目录不存在。unknown 只接受固定原因码。

每页保存带长度边界的 SHA256 回执。重新领取后可以精确重放已提交页，计数不重复；改变分类、跳页、旧租约、取消、根范围变化或基线版本变化都不能提交。交易末再次核对租约期限，迟到写入全部回滚。

## 基线版本与比较资格

成功的普通扫描原子递增库级基线版本，将本轮库存标记为该版本的观察。失败、取消、需要审核的扫描不推进版本。新字段不引用可能被历史清理删除的任务。

旧范围不可比时，分类状态明确结束且不宣称旧项缺失；后续完整扫描发布才可建立新范围基线。领域计算器的缺失分母只包含旧基线中本轮已见项与确认缺失项，排除项和新增项不能稀释缺失比例。当前证据未知或不完整必须审核。

当前版本仅提供分类存储和领域计算规则。排除旧项的保护合并、图片分类接线、来源复核与 seal、原生目录枚举、worker/API/CLI 接线继续下一段；enabled ignore 的领取与旧执行入口仍关闭，分类完成不授权发布。

## 迁移

当前程序要求 clean schema10；迁移001–009保持原文。010增加基线版本、分类状态、决定、回执及库存冻结触发器。保留任何分类状态或存在旧观察版本的保护基线时拒绝回退。没有这些状态时支持10→9→10；先停旧服务再迁移，不自动修复 dirty 标记。

## 验证

完整 PostgreSQL race 157 个顶层测试通过、零 skip；Windows domain 与 PostgreSQL 包测试及 vet 通过（Windows 未配置数据库，集成证据来自 Linux）；Linux 全模块 vet 和三个程序 build 通过。测试期间源码 SHA 不变，见[证据](evidence/ignore-baseline.json)。本段未重跑真实媒体验收。SQL执行计划使用10,000条旧基线和9,900条当前库存，检查128条原始页面只访问128条基线和128条库存索引结果。测试还覆盖空候选页、精确重放、领取恢复、取消、迟到回滚、真实祖先证明要求、历史删除和迁移保护。
