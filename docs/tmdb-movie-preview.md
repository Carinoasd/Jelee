# TMDB 電影候選資料與記憶體快取

這是第3階段的 G14 小段。正式 Go 服務已可透過管理員 API 依 TMDB 電影 ID 取得候選資料；完整自動刮削仍未完成。

## 使用與範圍

設定既有 TMDB_API_KEY／TMDB_API_KEY_FILE，並啟用帳號功能後，提供 `GET /api/v1/metadata/tmdb/movies/{id}?language=zh-TW`。必須通過既有 bearer 認證及管理員權限；未配置的逐步遷移模式不提供此路由，OpenAPI 同步隱藏。HTTP 建構時缺少中繼資料服務會拒絕半配置。

ID 必須是正整數 int32 的標準十進位字串。language 只接受 zh-CN／zh-TW／ja-JP／en-US；未指定時為 zh-CN，空值、重複、未知查詢參數或非法編碼回400。回應採既有 data envelope，包含來源 TMDB、標準來源頁面、語言、UTC 取得時間及選定的電影欄位。未知上游欄位不轉交；上游 homepage／圖片網址不會觸發抓取。

電影與認證使用同一個 runtime 擁有的適配器，因此共用250ms啟動間隔、四個請求容量、重試及429／503冷卻。每次取得最多15秒且接受呼叫者取消；電影正文1MiB，認證正文仍4KiB。選定欄位限制標題／原標題各1KiB、簡介16KiB；拒絕ID不符、空標題、非法日期、控制字元與原始API key回顯。404保留為not_found，其他供應商錯誤由應用層轉為固定503四語錯誤；不輸出底層URL／憑據／錯誤正文。

## 快取與生命週期

- 每適配器最多256筆，以ID＋語言為鍵，LRU淘汰；每筆從原始取得時間起24小時到期，命中不延長有效時間。
- 只儲存通過驗證的電影候選資料。認證、404、限流與其他錯誤均不快取；取消的快取查詢仍回取消。
- 回傳值只有字串、數字與時間，沒有共用可變陣列；呼叫者修改不會污染快取。同步鎖保護LRU／索引，較舊的並行回應不能覆蓋較新的資料。
- 快取未命中時仍可能重複查詢同一ID；本段沒有合併並行請求。正式HTTP入口受既有帳號請求容量限制，出站使用既有限流與四容量；沒有背景快取工作或新goroutine。
- 此快取不持久化，重啟清空。Fx生命週期在綁定監聽前驗證憑據，正常停止／啟動失敗／依賴圖失敗皆由同一closeOnce清理擁有的client，認證成功後保留client供API使用。

依據[官方電影查詢介面](https://developer.themoviedb.org/reference/movie-details)取得資料。[官方FAQ](https://developer.themoviedb.org/docs/faq)要求來源標示與核准標誌；配置TMDB後 `/api-docs` Credits 顯示來源連結、必要聲明及[官方標誌頁](https://www.themoviedb.org/about/logos-attribution)提供的未修改藍色短標誌。標誌由瀏覽器向官方域名載入，不經服務端抓圖；CSP只在該頁開放官方圖片來源。沒有將這段API文件當作完整前端歸屬展示或商業使用授權驗收。

## 驗證

已驗證管理員／一般使用者／未登入、非法ID與語言、未知及重複query、取消、四語安全錯誤、設定與OpenAPI一致；電影回應驗證、錯誤不快取、語言分區、精確24小時到期、TTL不延長、LRU容量、並行存取與新舊回應順序。

正式適配器經自有TLS服務與原受控transport測試專用DNS／CA／dial入口，連接應用層驗證兩次電影查詢只到上游一次、兩次認證仍到上游兩次。僅移除正式快取命中接線時，這項真TLS驗證失敗，上游收到兩次電影查詢；finally逐位元恢復，相關套件完整重跑通過。首次新增TLS測試建構參數與既有測試工廠不符，修正後才完成以下回歸，沒有把編譯失敗當成通過。

完整Go／vet／產品build與Linux六套件race结果、435個略過項目與前次清單的逐項核對，以及來源hash見[機器證據](evidence/tmdb-movie-preview.json)。略過不視為通過。
