# 項目 NFO 檔名選擇與可信觀察

正式 NFO 項目套用及唯讀庫的 TMDB 合併入口，現在都會從資料庫授權的唯一媒體來源選擇 NFO。HTTP 仍只接受項目 ID、版本與確認意圖，不接受檔案路徑。

## 檔名與優先序

同名 NFO 優先，例如 `folder/Film.mkv` 對應 `folder/Film.nfo`。其次為同目錄的 `movie.nfo`（Movie／HomeVideo）或 `tvshow.nfo`（Series）。只有檔名比對忽略大小寫，父目錄仍使用可信媒體來源的原路徑。

同一候選名稱有多個大小寫變體時拒絕歧義，不從目錄列舉順序選第一個。低優先候選的大小寫衝突、非一般檔案或符號連結也拒絕。當同名檔已存在，慣用檔名不會取代它；同名內容非法也不會悄悄改選其他 NFO。

## 觀察與保護

讀者先核對絕對根目錄、媒體檔、父目錄及路徑元件，拒絕符號連結、不可讀或不存在的媒體。透過 `os.Root` 有界列舉父目錄，每批 256 筆、最多 65,536 筆。完整列舉成功且沒有候選才回報內部 `nfo_item_absent`；超出上限、權限、I/O、根目錄或媒體問題均不能證明缺檔。

選擇觀察保存實際檔名與候選名稱集合的排序後 SHA256，僅在內部使用。每次讀取前後重核根目錄、父目錄與媒體身分，再由原安全讀者讀取完整 NFO。NFO-only 套用前，以及 TMDB 網路查詢前後，都重新選擇並比對檔名、候選集合、完整檔案戳／雜湊、解析身分、欄位及鎖意圖。新增較高優先檔，或新增低優先候選但保留相同選中內容，仍拒絕 409。

列舉持有的檔案 handle 在取消時關閉，取消 callback 被等待並結束；每批與路徑檢查均核對 context。原有欄位優先序、一次版本／稽核、最終資料庫權限／來源／世代重驗及原子回滾保持。選中檔名與根路徑不進 API 或稽核。

## 實際驗證

真 HTTP／TLS／安全 NFO／PostgreSQL 驗證同名優先、大小寫、`movie.nfo`／`tvshow.nfo`、查詢中較高優先檔出現與次要候選新增、歧義在外呼前被拒絕；NFO-only 真 HTTP／PG 也套用大寫 `MOVIE.NFO`。

Linux 原生檔案測試驗大小寫碰撞、候選／父目錄／媒體符號連結、非特權 process 的 mode 000 權限錯誤，以及超過上限的完整實際目錄。缺 NFO、缺媒體／父目錄／根目錄、候選是目錄、非法 XML 與取消分別驗分類。兩個正式路徑負例分別反轉檔名優先序及停用候選集合比較，必須失敗，再逐位元復原。執行數與來源雜湊見[證據](evidence/nfo-item-selection.json)。

## 尚待接續

本次補上來源選擇；缺失或非法 NFO 的 HTTP 行為仍為 503。供應商安全回退需要缺失／損壞的可重核觀察及保存狀態，尚未啟用。慣用檔名只支援目前 Movie／HomeVideo／Series 四文字欄位；season／episode、包裝、多項目、其他欄位、匯入階層、worker、read-write 無損寫回及前端仍未完成。

這些檢查點不是檔案系統原子快照。最後觀察後仍可能變動，阻塞 open／stat 與檔案系統操作無硬性取消保證。原媒體、NFO、圖片、授權及既有遷移保持。G39、第三階段與全案仍未完成；全量品牌與 ABI 仍有失敗。
