# G11.2 可信代理設計

狀態：CIDR／XFF與帳號接線已實作，驗收見[可信代理](../trusted-proxies.md)；完整公網部署矩陣尚未完成。依原始G11.2與使用者要求自主逐階段完成的授權，以下例行設計選擇由維護者執行；這份設計不套用仍待核准的直播五檔刪除。

## 問題與需求

設計起點的登入限流和帳號稽核只使用傳輸對端，忽略全部轉發標頭。反向代理下所有使用者共用代理IP額度。G11.2要求只有設定CIDR內的代理可提供轉發資訊，未匹配的標頭須忽略並告警。公開Host驗證與帳號權限不能因轉發標頭改變。

## 方案選擇

| 方案 | 結果與成本 |
| --- | --- |
| 保持只使用傳輸對端 | 不符合可信代理需求，多名使用者仍共用額度 |
| CIDR白名單＋嚴格X-Forwarded-For鏈 | 採用；處理常見代理地址鏈，來源與資源預算清楚 |
| 同時解析RFC Forwarded及多種供應商標頭 | 需處理格式、優先順序與衝突；待有實際客戶端需求再擴充 |

地址來源只採X-Forwarded-For。Forwarded、X-Real-IP、轉發Host／Proto不參與身份、權限或URL重建。這是本階段的明確協定範圍；G11.1允許目前的相對URL，PublicBaseUrl屬可選替代，沒有將其擴張為必須新增的功能。

## 設定與生命週期

- 新增JSON `trustedProxies` 字串陣列與環境變數 `JELEE_TRUSTED_PROXIES`（逗號分隔CIDR）。環境變數優先，空字串表示不信任代理。
- 預設空集合，保持目前直連行為；最多64個前綴，解析錯誤使啟動失敗。錯誤訊息只指出設定名稱，不回顯地址或原值。
- 前綴正規化為Masked；IPv4映射IPv6地址／前綴須與現有ClientIP的Unmap策略一致，不容許zone。HTTP建構時複製不可變前綴，請求不重新讀取環境。

## 地址解析與信任邊界

1. 使用既有ClientIP解析並正規化傳輸對端。無效對端維持空地址，登入限流保持既有拒絕行為。
2. 對端未命中CIDR時，完全忽略轉發地址。若帶Forwarded、X-Forwarded-*或X-Real-IP，記一筆告警。
3. 對端可信且有X-Forwarded-For時，合併多個同名標頭，最多8192位元組／32個節點。只接受有效IP字面值，剝除空白並Unmap；不接受zone、主機名或帶port的節點。
4. 先驗證整條鏈，再由右向左剝除可信代理，第一個未可信位址作客戶端。全部節點可信時使用最左位址。空節點、超限或非法節點回退傳輸對端並告警。
5. 將有效地址放入私有request context供登入、帳號稽核及密碼操作使用；不覆寫RemoteAddr。無該context時保持傳輸對端回退。

Host允許名單照常使用實際Host；身份／會話類型仍由資料庫決定。可信代理必須清理／正確追加客戶端提供的X-Forwarded-For，來源主機防火牆須由部署限制。

## 告警與隱私

每個請求最多一筆固定事件，包含component、requestId及固定reason（untrusted_peer／invalid_chain）。不記錄完整轉發鏈、IP、路徑、query、Cookie、Authorization或密碼。沒有轉發標頭時不新增告警。既有完成日誌維持。

## 實作順序與驗收

1. 新增設定解析／驗證，覆蓋預設、JSON、環境優先、空值、非法CIDR、IPv4／IPv6／mapped、64項上限與錯誤不含原值。
2. 新增私有解析器與單元驗收：不可信偽造、可信單層／多層、右側未可信邊界、全可信、重複標頭、空節點、zone／port／主機名、位元組／節點超限。
3. boundary注入有效地址與固定告警，帳號入口使用context地址。實际HTTP fixture驗證可信代理的不同客戶端限流分離、不可信／錯誤鏈仍共用傳輸額度、稽核地址來源、標頭不提升角色／Host、不洩漏原值。
4. 補真loopback HTTP代理與來源的請求；此驗收證明程式接線，不能代替公網／防火牆驗收。
5. Windows受影響HTTP/config回歸、vet，Linux race；必要Go完整回歸與現有翻譯門禁。更新網路文件，依實際證據更新G11.2。最後執行品牌／gitignore／來源保護檢查、提交推送同PR46。

## 自我審查

設定預設、地址來源、解析失敗、有限資源、日誌欄位、角色／Host邊界及驗收均已明確。新功能不涉及資料庫遷移、媒體寫入、C#核心刪除或外部部署。RFC Forwarded支援與URL重建不宣稱已完成；CIDR／XFF帳號接線已驗收；完整公網部署矩陣仍未完成。

參照[網路隱私現況](../network-privacy.md)及原始G11.2需求。[RFC 7239 §8.1](https://datatracker.ietf.org/doc/html/rfc7239#section-8.1)說明轉發資訊可能被修改，須根據可信代理邊界使用。
