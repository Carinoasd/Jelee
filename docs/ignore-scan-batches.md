# 忽略規則掃描批次保存

本階段提供 PostgreSQL 儲存介面，尚未開放 enabled 工作領取，也尚未接入 worker/API。

## 原子保存

`SaveIgnoreScanBatch` 在同一交易核對租約、epoch、目錄狀態與完整祖先證明，保存包含項目、子目錄及排除來源。批次合計最多 128 項；證明最後一項必須符合列舉時持有的目錄身份。來源衝突持久標記失效，但不保存該批庫存。

排除紀錄保留路徑、類型、規則所在目錄、行號與匹配路徑。相同紀錄重送不重複計數；包含與排除不可重疊。排除檔案和目錄分別計入原有檔案與目錄容量限制，不進入庫存或待掃描佇列。超限、失去租約或 epoch 改變均回滾交易。

`NextIgnoreScanDirectory` 清除未完成目錄的部分庫存及排除計數，保留已固定的來源證明。開始基線比對或凍結來源後，不允許再保存或重掃；資料庫觸發器同時禁止修改排除紀錄。

## 遷移與歷史清理

新增 schema 012，既有 001–011 不變。有保留掃描狀態時拒絕降級；刪除工作歷史後可降回 011。排除紀錄對工作目錄使用 ON DELETE CASCADE，讓歷史清理不受多條外鍵級聯順序影響。仍存在工作的凍結限制由觸發器保護。

## 驗證範圍

整合測試涵蓋重送、重掃、發布、不列舉排除目錄、來源衝突、來源歸屬、重疊、容量及租約到期回滾、比對後凍結、歷史清理與降級。這些資料庫測試不代表原生檔案系統與 worker 的端到端驗收已完成。
