# 舊格式忽略規則：來源觀察保存

本段接續 PR #31 的最近來源觀察，新增領域合同與 schema 13。仍屬 G22.2、G22.3 的部分交付；尚未開啟舊格式掃描。

## 保存合同

- 每次觀察包含根目錄至查詢目錄的完整父鏈，最多 129 個目錄。`Checked=false` 表示被更近來源遮蔽，不能當作來源不存在。
- `job_ignore_legacy_proofs` 保存目錄身份與來源證據；`job_ignore_legacy_queries` 另外保存查詢目錄、選定來源及版本，避免合併目錄證據時失去各次最近來源查詢的邊界。
- 未檢查的來源可以補查。已查來源的存在、內容雜湊、大小、時間或身份發生變動，或目錄身份不同時，整份清單失效。衝突只提交失效標記，不保留該次新增內容。
- 重複觀察不重複計費。上限為 16,384 個目錄、16,384 次不同目錄查詢、64 MiB 來源位元組與 64 MiB 計費量；另受任務的目錄上限限制。計費量是確定性預算，並非 PostgreSQL 實際磁碟占用。
- 既有父鏈以一次有界查詢讀取，寫入使用 pgx batch，避免每個目錄等待一次資料庫往返。
- 凍結前每個媒體根都必須有明確的根目錄查詢；只有深層查詢中的未查祖先不足以證明根覆蓋。凍結後只允許相容重播，分頁最多 128 筆，使用 UUID 與 C collation 路徑排序。
- 保存、凍結、分頁均重新檢查租約、取消與媒體庫世代；提交前再次檢查租約期限與世代。失效不會回傳部分讀取結果。

## 遷移與能力邊界

001–012 遷移保持原樣。新增遷移只接受既有自有模式版本組合，以及預留的 `jeleeignore-legacy-v1` 組合；不能混搭版本。舊模式不能建立舊格式清單。存在預留模式請求或清單時，down 明確拒絕；刪除任務會連帶清除資料，之後才能回到 schema 12。

預留模式尚未經公開 API 接受，既有工作領取與掃描執行守衛保持關閉。測試使用隔離資料庫製造請求及租約，只驗證保存層。這些方法不代表已完成規則比對、來源最終復核或基線發布。

## 驗證入口

- 領域：`go test ./internal/domain`，最近來源父鏈、影子祖先、來源不存在、版本、身份、相容合併與資料脫敏。
- 資料庫：`go test -race ./internal/adapter/postgres`，其中 `TestLegacyIgnore*` 驗證遷移、模式隔離、單調補查、重播、衝突、預算、凍結、分頁、租約、取消與世代。
- 真實整合測試須配置專用 `JELEE_TEST_DATABASE_URL` 並設 `JELEE_REQUIRE_INTEGRATION=true`；無資料庫的套件測試不能算整合通過。

Linux 真實 PostgreSQL 全套 race：193 項頂層測試通過、0 失敗、0 跳過，耗時 240.316 秒，測試前後來源雜湊一致（本機證據 `.testdata/inventory-legacy-storage-fixed-postgres-summary.json`）。首輪曾有 6 個舊降版測試漏掉 13→12 步驟，補齊後全套通過。Linux 領域／架構 race 通過（1.102／1.130 秒）；Windows 全套測試除 toolidentity 的環境 ACL 限制外通過，該套件在允許 ACL 的環境重跑通過（0.296 秒）。Windows 全模組 vet、三個命令建置、增量品牌掃描（0 違規／100 合法命中）、gitignore-check 通過。

## 後續

仍需整個任務的來源復核檢查點及發布守衛、既有目錄消失時的基線合同、兩種規則組合、解碼與批次匹配、正式 worker／API／報告接線。其餘舊格式來源調查與全量相容驗收仍未完成。

## 查詢還原與單次原生復查

`ReadLegacyIgnoreObservationPage` 每頁最多還原 16 次查詢。先讀取查詢，再合併取得祖先證據，最多 16×129 筆；不逐目錄往返資料庫。游標由最後一筆查詢的 root ID 與目錄組成。凍結、有效世代及有效租約是讀取前提，取消或失效不回傳部分結果。

`RestoreLegacyIgnoreObservation` 按保存的選定來源還原原始邊界。某祖先在別次查詢已補查，不代表本次查詢也曾讀取它；還原時保留其身份，但清除本次查詢被遮蔽的來源證據。缺父鏈、未查的必要來源或選定來源不符均拒絕，不修改原始合併清單。

掃描配接器新增 `ObserveLegacyIgnore` 與 `ReobserveLegacyIgnore`。後者重新执行兩次原生最近來源觀察，比對整條身份與來源證據。來源刪除、同大小同時間戳改文、下層新增空規則都使舊查詢失效；被遮蔽祖先的規則變化不影響該次查詢。目錄消失回錯誤，尚未實作缺失目錄的基線語義。

本段驗證：Windows domain／scan／postgres／architecture 測試、全模組 vet 與三個命令建置通過。Linux 原生 `/tmp` domain／scan／architecture race 分別 1.050／1.169／1.086 秒。真實 PostgreSQL `TestLegacyIgnore*` race 8 項頂層測試通過、0 跳過，23.422 秒；來源前後雜湊一致，包含保存→凍結→還原→原生復查，以及新增更近來源的拒絕（本機證據 `.testdata/inventory-legacy-query-native-postgres-summary.json`）。

以上只證明歷史觀察還原與單次來源復查；尚未建立整個任務的持久驗證進度或允許發布基線。schema 保持 13，預留模式的公開入口仍未啟用。
