# 唯讀 NFO 的可信回退與確認狀態

當前binary要求schema25；本頁保留先前階段的契約與證據。缺少文字值時的獨立NFO鎖及升降版限制，見[第25版契約](nfo-field-lock-intent.md)。

唯讀庫在明確確認套用 TMDB 時，先從可信項目／媒體／根目錄關係取得 NFO 觀察，再查詢供應商。狀態決定欄位來源：

| NFO 觀察 | 套用行為 | 保存的檔案戳 |
| --- | --- | --- |
| `valid` | 先套用 NFO，再補 TMDB；人工值及鎖保持保護 | 完整原始 bytes 的 SHA256、大小、時間戳 |
| `missing` | 完整安全目錄觀察確認缺失後，使用 TMDB | `null`，不偽造 NFO 欄位或來源 |
| `nfo_invalid` | 完整安全讀取後的 XML／編碼解析損壞，使用 TMDB | 損壞原始 bytes 的完整檔案戳，不保留部分欄位 |

權限錯誤、符號連結、候選名碰撞、大小／目錄界限、危險 XML、未支援編碼及取消不觸發回退。有效但尚未支援的空內容、只有鎖指令、包裝、多項目、種類不符或重複欄位／鎖意圖也保持拒絕。NFO-only 入口仍只接受有效內容；缺失或損壞回 503。

## 查詢期間與同次交易

供應商請求不持有資料庫交易或檔案 handle。請求結束後，正式讀者重新觀察狀態、原始 bytes、候選名稱，以及根目錄／父目錄／媒體／NFO 的實體身分。缺失後出現、損壞修復、相同大小／時間戳下改動損壞 bytes，均回 409。檔案系統重核是檢查點，最後檢查後仍可能變動。

最終交易重驗 session、項目版本、種類、媒體來源、根路徑及 NFO 世代。欄位、目錄標題、HomeVideo 分類、確認狀態、一次版本增加及一次套用稽核共同提交。供應商失敗、取消、來源變更、狀態保存失敗或稽核失敗都不留下半份更新。既有人工空值、NFO 來源及兩類鎖繼續阻止覆蓋；全部欄位受保護時，確認仍增加一次版本並保存觀察。

`nfo.status` 明確說明本次觀察。`metadata.lastConfirmedNFOObservation` 保存最後一次確認的狀態、歷史來源／根 ID、世代、解析身分摘要、候選摘要、讀取時間、確認版本及可選檔案戳。這是確認歷史，不代表目前檔案仍相同；人工編輯會增加目前版本，但保留原確認版本。沒有既存觀察時為 `null`。資料不含檔名、根路徑、NFO 文字欄位或私有檔案資訊。

## 第 24 版資料庫

新表 `item_nfo_observations` 以項目為鍵，保存最後一次安全觀察；項目刪除會連帶清除紀錄，歷史來源／根 ID 不因來源移除而失去識別。JSON 有固定鍵、版本、狀態、UUID、雜湊、有限時間、整數範圍與 2 KiB 上限；缺失必須沒有檔案戳，存在／損壞必須有完整戳。不能直接保存私有讀者物件。

服務要求乾淨 schema24，先遷移再啟動。001–023 保持；保留觀察時降版拒絕丟失紀錄，沒有觀察時可 24→23→24。人工改值不清除此歷史。正式外部元資料清除功能仍待實作。

## 驗證與範圍

實際 HTTP／受控 TLS／安全 NFO／PostgreSQL 驗證三態回退、一次版本／稽核、查詢期間的狀態與原始內容變更、權限／危險 XML／鎖指令拒絕、供應商失敗及取消。刻意停用正式讀者與應用層的原始戳比較，完整路徑會錯誤接受已變更的損壞 bytes 而失敗；逐位元復原後通過。資料庫驗狀態／欄位／稽核回滾、人工歷史保留、舊 NFO／空值保護、紀錄約束及降版拒絕。完整執行結果見[證據](evidence/nfo-tmdb-fallback.json)。

目前只支援既有四欄文字投影。季／集、其他欄位、實際匯入與階層 worker、無損回寫、外部來源清除、前端及完整效能仍未完成。G14／G39、第三階段及全部 336 項仍未完成。
