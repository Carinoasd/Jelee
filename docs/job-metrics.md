# 工作持久統計與資料庫快照

schema45 保存工作結果、首次等待時間與工作耗時，清理舊工作或刪除媒體庫時保留累計值。內部 `JobMetricsSource` 讀取介面已接到管理員 [`/metrics`](metrics.md)，透過正式 OTel／Prometheus exporter 輸出固定工作系列。

## 計數方式

資料庫 trigger 在工作狀態改變的同一交易中更新統計。工作交易、savepoint、最後發布檢查或 audit 寫入若回滾，統計一起回滾。心跳、進度與取消旗標本身不增加樣本。

| 統計 | 計算時點與意義 |
| --- | --- |
| 成功／失敗／取消總數 | queued 或 running 實際轉為對應終態時加一 |
| 首次等待 | 第一次 queued→running，從 created_at 到 started_at |
| 工作耗時 | 有 started_at 的工作進入終態，從首次 started_at 到 finished_at，包含重新排隊間隔 |
| 排隊數與最舊年齡 | 目前 queued 工作；年齡從首次提交起算 |
| 執行數 | running 且租約尚未到期；不代表當下 CPU 正在執行 |
| 過期執行數 | running 且租約已到期；讀取統計不接手或延長租約 |

同 ID 釋放後重新 claim 只保留一個首次等待樣本。產品 Retry 會建立新工作，獨立計數；同 key 重送仍沿用既有工作。從未開始就取消的工作只有取消計數；曾開始、重排後取消的工作仍有耗時。`review_required` 的成功掃描照成功計算。時間差使用資料庫微秒，遇到時鐘倒退取零。

統計只使用兩種 kind（inventory_scan、catalog_import）及兩種 priority（manual、background）。固定一列 epoch、四列累計、104 列分桶，共 109 列；不保存逐工作指標事件，不包含帳戶、路徑、媒體庫、owner 或連線資訊。

## 等待與耗時分布

每個觀測只增加一個互斥桶。最後一桶為 +Inf。OTel cumulative histogram 直接使用桶計數；Prometheus exposition 才轉成累積的 le 桶，不能每次讀取都重播 `Histogram.Record`。

- 等待上界（秒）：0.1、0.5、1、2.5、5、10、30、60、300、1800、3600、86400、+Inf。
- 耗時上界（秒）：1、5、10、30、60、300、900、1800、3600、7200、21600、86400、+Inf。

等於上界的樣本屬於該桶。計數以非負 bigint 保存，時間總和以 numeric(30,0) 保存精確微秒。讀取時驗證固定組別、桶數、非負值及桶總數，轉成 float64 秒供監控使用；累計超過 float64 的整數精度範圍後，對外數值可能失去微秒精度，資料庫原值仍保留。

## 一致讀取與多副本

介面用單一 SQL statement 取得 epoch、累計、分桶與當前工作，使用同一 MVCC 快照與資料庫觀察時間。只查活動工作與小型聚合表，不讀清單／快照內容、不取得 jobs advisory lock、不執行恢復寫入。context 最多兩秒，包含等待連線；缺少固定資料或查詢失敗時回傳錯誤及空結果，不能把失敗當成零值指標。

這些數值屬於共用資料庫 schema。多個服務副本讀到相同累計，不能將它們相加；端點的 OTel 指標使用 `jelee.jobs.shared.*` 名稱，部署時選一個收集目標或先依有限 cluster 維度去重再求速率。cluster 由 scrape 設定提供，不把 DSN 或 schema 名稱轉成 labels。

## 遷移與降版

001–044 的既有 SQL 保持不變。up45 暫時鎖定工作狀態寫入，在同一交易建立零值統計、epoch 與 trigger。啟用前已完成的工作不回填，因為已清理的歷史無法重建；啟用前正在執行的工作，之後完成會記錄結果及完整耗時，其首次等待不補記。因此等待樣本數與耗時樣本數不必相等。

空統計可以 down45→44。已有樣本或固定資料不完整時，down45 拒絕執行，防止遺失歷史。遷移工具失敗可能留下 dirty 標記，必須先查明資料庫狀態，不能直接 force 版本或刪表。未提供統計重置操作。

trigger 使用呼叫者權限，依擁有 jobs 的 schema 定位統計表；呼叫者的 search_path 或同名暫存表不能改寫記錄目的地。缺少必要 epoch／累計列／目標桶時，工作轉換整筆失敗，避免悄悄漏計。
