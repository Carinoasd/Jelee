# NFO 缺值欄位的獨立鎖定

第三階段 G14.6／G39.6 的四欄位子集。此頁說明第25版的新契約；[實測證據](evidence/nfo-field-lock-intent.json)。

## 行為

有效 NFO 即使只提供標題，`lockdata=true` 仍保護標題、原始標題、概要和日期。`lockedfields` 的 Name／OriginalTitle／Overview／PremiereDate 分別對應這四欄，忽略大小寫與首尾空白。未知名稱保留在原始 NFO，不建立未支援欄位的鎖。

鎖定指令保存於獨立的 `item_nfo_field_locks`，不要求文字欄位已存在。回應的 `nfoLockOrigin` 與 `nfoOrigin` 分開：前者證明鎖定意圖，後者只證明實際採用的 NFO 文字。鎖定原本的 TMDB 欄位不會改變文字值、來源、供應商歸屬或更新時間。尚無文字值的鎖定欄位以空值及 existing 來源呈現，沒有文字來源證明。

保存的鎖定證明含歷史 source／root ID、generation、完整原始 bytes 戳、解析身分摘要、投影版本、讀取時間與正鎖定值，不含路徑或文字值。這不是目前檔案狀態的保證。

## 交易與人工接管

NFO 文字依既有來源及鎖規則套用，再保存正鎖定指令。融合交易重新讀取鎖定狀態後才套用 TMDB；欄位、鎖、確認觀察、目錄、版本及稽核一起提交。NFO-only 與正式 NFO／TMDB 融合共用此實作。

已有 NFO 鎖持續保護後續 NFO 和 TMDB 更新，包括媒體庫切換 off 後的 TMDB-only 確認套用。後續 NFO 沒有鎖定指令，不代表解除既有鎖。

人工更新文字或明確清空選用文字時，同一交易刪除該欄的獨立 NFO 鎖，清除文字來源證明並建立 manual 來源。只修改人工 `locked` 開關會保留 NFO 鎖；設為 false 不能繞過它。任一 SQL 或稽核失敗，鎖定與人工接管都回滾。

## 遷移

binary 要求乾淨 schema25，啟動前先遷移。001–024 保持不變。新表以項目與四欄名稱為主鍵，項目刪除時連帶刪除；歷史 source／root 不依賴目前來源列仍存在。SQL 約束固定 JSON 欄位、型別、版本、摘要、原始戳、時間與大小上限。保留任何獨立鎖時，25→24 降版拒絕刪除；沒有鎖時允許乾淨降版及再升版。

## 尚未涵蓋

目前仍使用 four-text-fields-v1，有效 NFO 至少須有一個支援的非空文字欄位。只有鎖定指令、沒有任何四欄文字的有效 XML 尚未支援，仍回503；這是下一個切片。其他 NFO 欄位、季／集、多項目來源、完整前端及 read-write 無損回寫仍未完成。原始 NFO 和媒體不會被這個唯讀套用流程寫入。
