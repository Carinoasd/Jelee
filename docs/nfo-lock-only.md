# 只有鎖定指令的 NFO

第三階段 G14.6／G39.6 的四欄鎖定子集。第26版擴充[獨立欄位鎖](nfo-field-lock-intent.md)，讓有效的 lock-only NFO 進入正式唯讀套用流程。

## 讀取與保存

`<movie><lockdata>true</lockdata></movie>` 沒有文字值，仍能建立標題、原始標題、概要與日期的鎖。`lockedfields` 只鎖已支援的 Name／OriginalTitle／Overview／PremiereDate；至少有一個已知正鎖定指令，才接受沒有文字的投影。大小寫及首尾空白規則沿用既有四欄鎖。劇集 tvshow 與受支援的文字編碼使用相同流程。

讀者使用獨立版本 `lock-only-fields-v1`，文字欄位陣列為空。既有 `four-text-fields-v1` 仍要求至少一個非空、可支援的文字值。新投影通過可信項目／來源／根目錄觀察，保存完整原始檔案戳，跨供應商查詢重新核對，並在最終交易檢查授權、版本及來源範圍。

正式觀察狀態為 valid。套用保存獨立 `nfoLockOrigin` 及安全的確認觀察，既有文字值、文字來源、供應商歸屬及文字更新時間保持。沒有文字值的欄位以 existing 空值加鎖呈現。原始 NFO 與媒體維持原樣。

空文件、只有未知鎖名稱、只有 false 鎖定值，且沒有支援文字的有效 XML 仍回503。它們不會觸發缺失或損壞 NFO 的 TMDB 回退。危險 XML、權限問題、歧義檔名及不完整來源觀察繼續拒絕。

## 套用與人工接管

NFO-only 只保存鎖與觀察，推進一個版本並建立一次稽核。HomeVideo 分類保持；NFO-only 沒有供應商查詢。

與 TMDB 融合時，先保存 NFO 鎖，再套用供應商文字。全欄鎖會略過四個供應商欄位；指定欄位鎖允許其他欄位更新。只有實際套用文字才會讓 HomeVideo 轉為 Movie。每次確認保存單一版本與稽核。

人工文字修改或明確清空同交易解除該欄位的 NFO 鎖；只調整人工鎖開關保留它。庫切到 off 後，已有的 NFO 鎖仍保護 TMDB-only 更新。查詢期間鎖定指令變更會拒絕提交。供應商、SQL 或稽核失敗會回滾欄位、鎖、觀察、分類、版本及稽核。

## 遷移

binary 要求乾淨 schema26，啟動前先遷移。001–025 保持不變。第26版只擴充獨立鎖的投影約束，既有安全 JSON 欄位、型別、原始戳與大小限制保持；文字來源的 NFOItemOrigin 仍使用四文字投影。

保留 lock-only 證明時，26→25 降版拒絕。只有四文字投影的舊鎖時可降至25，證明內容保持；25→24 仍受第25版的保留鎖保護。沒有新投影證明時可乾淨降版再升版。

## 範圍

目前只有上述四個文字欄位及其鎖。其他 NFO 欄位、季／集、多項目來源、實體匯入與 worker 層級、前端、read-write 無損回寫及外部資料清除仍待完成。檔案觀察使用檢查點，沒有提供持續的原子檔案快照。
