# 掃描候選匯入：第一段

接通本機管理 CLI 的單筆確認流程：指定已完成掃描的 job 與 inventory ID，重新核對檔案，再以短交易建立 catalog item／media source。影片種類、標題與可選單集父層由操作者明確提供。

候選必須屬於成功且不需覆核的最新掃描；根世代、已接受基線的最新觀察、種類、size 與 mtime 均須一致。重新掃描、根變更或基線變更會使舊候選失效。忽略規則排除而保留的歷史基線不能成為候選。DB 提交重新讀取整個候選，防止檔案檢查期間狀態改變。

沿用本機 CLI 的資料庫管理權限，HTTP 入口另段接入登入與即時管理權限。只登記明確選定的影片；不猜測整庫命名，不自動刪除缺失項目，不代表已完成 probe 或 NFO 套用。原檔保持不變。

驗收採真實檔案、正式 Scanner、隔離 PostgreSQL 與實際 CLI：成功後 catalog 可見；重複、未完成、過期、覆核、檔案變更與來源符號連結拒絕；交易故障不留下部分資料。單筆流程不宣稱批次吞吐或全庫自動匯入完成。

檔案核對是 size／mtime 的檢查點，不能識別同 size／mtime 的原地內容修改，也不能保證核對後原檔永遠不變。已有播放來源守衛繼續生效。
