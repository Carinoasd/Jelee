# NFO 年份有型別保存

年份由正式 NFO Reader 以整數提取，經既有來源所有權、兩次觀察與交易守衛確認後，保存到 `item_metadata_facts.value` 的 JSONB 數字。API 的 `metadata.facts` 與文字 `fields` 分開，年份值為 `2024`，範圍為 1–9999。

新增固定 `year-fact-v1` 投影，涵蓋九個既有文字欄位與年份。舊四欄、五欄及九欄版本的集合維持原樣。年份值、`Year`／`ProductionYear` 鎖會選用新投影；只有鎖而沒有值時，回應 `value: null`、`source: existing` 與獨立鎖定證明，不虛構 NFO 值來源或更新時間。年份在來源重核時一併比較，觀察資料與 API 回應的複製保護可變切片。

NFO-only 與 NFO／TMDB 融合共用保存流程：文字、數值、鎖、確認觀察、版次與稽核在同一交易提交。已人工修改或已鎖定的年份不被 NFO 覆蓋；TMDB 目前仍只產生既有四個文字欄位。

管理員可在既有 metadata PUT 一起送出 `fields` 和 `facts`，或只送其中一種。`facts[].value` 省略時保留值，數字表示人工接管，`null` 表示明確人工清除。人工給值或清除會解除該年份的 NFO 值來源與獨立鎖；只改 `locked` 旗標保留 NFO 鎖。人工清除與人工數字同樣受來源優先權保護，之後的明確 NFO 確認仍可保存新的正鎖定意圖。

JSON 解碼只在 `facts[].value` 允許 `null`，其餘位置、文字值、重複屬性、未知欄位與無效型別仍拒絕。例：

```json
{"expectedRevision":2,"facts":[{"field":"year","value":null}]}
```

第 29 版遷移新增有型別資料表與嚴格值、來源證明及年份鎖約束。只要保留年份資料（包括人工清除）、年份鎖或新投影來源證明，就拒絕降到第 28 版。第 1–28 版遷移保持原樣；歷史降版測試明確先經 29→28。

本段只完成年份的正式套用與人工修改。片長、評分、人物、多值、季集來源、實際匯入、前端與 NFO 無損寫回仍待完成。全案仍第三階段；G39.3／G39.6 保持部分完成。驗證見下方實測。
