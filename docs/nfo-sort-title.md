# NFO 排序標題的確認套用

第 27 版將 `sorttitle`／`sortname` 接到正式 `sortTitle` 欄位。Movie、Series 及可確認為 Movie 的 HomeVideo 支援 NFO-only 與 NFO／TMDB 同交易融合。兩個排序標題標籤共用單值計數；重複、大小寫變體或混合別名都拒絕，巢狀人物名稱不受影響。原 NFO、媒體及圖片保持。

## 值、來源與鎖

`sortTitle` 是可空的 UTF-8 文字，最多 1024 bytes；NFO 中缺值不清除已有值。人工明確空值是持久化的接管，優先於後續 NFO。NFO `SortName` 欄位鎖與全域鎖保存獨立來源證明；沒有排序標題文字時，指定鎖也能保存，回傳空的既有欄位與鎖來源，不虛構 NFO 文字來源或更新時間。人工文字接管清除該欄鎖，後續明確 NFO 確認仍可再次保存正鎖；人工值保持。

新 `five-field-projection-v1` 最多五欄，無文字時須有已知正鎖。原 `four-text-fields-v1` 仍最多四欄且不接受排序標題；原 lock-only 投影仍只保護舊四欄。舊投影全域鎖不會在升級時默默新增排序標題鎖。TMDB 確認仍只提供既有四欄，沒有虛構排序標題的供應商來源。

API 欄位、人工 patch 與套用報告上限更新為五欄。最終交易沿用項目／來源／世代／session／revision 重核，NFO 與供應商共同只推進一次版本、一次稽核。欄位、鎖、觀察與稽核任一失敗皆回滾。

## 遷移

新增 `000027_nfo_sort_title`，保留 001–026。欄位與鎖的鍵限制、值長度及兩種來源證明的投影限制一併擴充，其餘嚴格 JSON 及數值條件保持。排序標題不能持有舊 NFO 投影或 TMDB 來源。27→26 會先鎖表並拒絕丟棄任何排序標題欄位或新版投影證明；人工清空仍是資料，不能藉降版刪除。

## 範圍

本段只是增加一個文字欄位。其他文字／數值／多值、人物、評分、IDs、季集來源、實體匯入、前端與無損回寫仍未完成；G39 保持部分完成。[範圍](nfo-compatibility.md)。
