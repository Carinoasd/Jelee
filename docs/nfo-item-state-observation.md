# NFO 有效、缺失與損壞的可信觀察

當前binary要求schema25；本頁保留先前階段的契約與證據。缺少文字值時的獨立NFO鎖及升降版限制，見[第25版契約](nfo-field-lock-intent.md)。

本頁保留該階段的實作與驗證；後續第24版的三態保存及可信缺失／損壞回退，見[最新回退契約](nfo-tmdb-fallback.md)。

正式讀者現在分別保留 `valid`、`missing`、`nfo_invalid`。這是 TMDB 回退的前置觀察能力；狀態保存與回退尚未啟用，NFO-only 和 TMDB 套用遇到初始缺失／損壞仍回 503。

缺失必須經完整、有界的安全目錄觀察確認，沒有檔案戳、欄位、NFO 來源或鎖。損壞僅接受已安全讀取完整原始 bytes 後的 XML／編碼解析失敗，保存原始 SHA256、大小與時間戳，沒有部分欄位。權限、連結、大小／目錄界限、危險 XML、未支援編碼及取消等錯誤保持拒絕。有效但尚未支援的空內容、只有 lockdata、包裝、種類不符或重複欄位／鎖意圖，也不當作可回退的損壞。

讀者重核狀態、解析身分、完整檔案戳、候選名稱及根／父目錄／媒體／NFO 實體。缺失後出現、損壞修復、相同大小與時間戳下改動損壞 bytes，均拒絕為来源變更。觀察物件不保留開啟的 handle，欄位及鎖清單取得時複製；私有路徑和檔案資訊不進 API 或稽核。

## 驗證

- Windows 全 Go：29 套件、3214 通過事件含父、457 測試略過，略過身份與前一階段完全相同。
- Linux 原生暫存目錄五套件 race：1080 通過事件含父、0 失敗、0 略過。
- PostgreSQL 的 NFO 項目 race：5 通過事件含父、0 失敗、0 略過；完整實際 HTTP／TLS／安全 NFO／PG 測試通過，含兩入口的初始缺失／損壞守衛、無供應商請求／目錄變更／套用稽核，以及既有融合與 120 筆合成確認寫入。
- 刻意移除正式讀者的原始 bytes 戳比較，實檔測試會接受相同大小／時間戳但已變更的損壞內容而失敗；逐位元復原後通過。此負例驗讀者層；回退 HTTP 路徑尚未實作。
- vet、產品 build、增量品牌與 gitignore 通過。授權文件、需求原文、五個待授權核心及 001–023 遷移保持。詳見[證據](evidence/nfo-item-state-observation.json)。

## 下一段

新增項目觀察的安全持久化，與欄位／分類／版本／稽核在同一次交易提交；供應商失敗、取消、來源變更或 SQL 失敗不留下半份狀態。只有有效 NFO 套用其欄位，可信缺失／損壞才允許供應商回退，人工值與既有 NFO／鎖仍保護。保留最後確認的安全狀態，明確區別於目前檔案的新鮮度。

目前 schema23、G39.6 仍部分完成。季／集、其他欄位、實際匯入／worker、無損回寫、外部來源清除和前端仍待完成。檔案重核並非原子快照，最後檢查後仍可能變動。
