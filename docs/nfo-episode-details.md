# 單集 NFO 的來源與中繼資料

第 38 版接上既有 Episode 條目與真實影片來源。只採用影片同名的 `.nfo`（副檔名及檔名大小寫不敏感），接受 `episode`、`episodedetails` 單一根元素；不採用旁邊其他影片、`movie.nfo`、`tvshow.nfo` 或 `season.nfo`。

## 欄位契約

| 欄位 | 值 |
| --- | --- |
| seasonNumber、episodeNumber | 0–1,000,000 的整數，缺省與零有別 |
| displaySeason、displayEpisode | 同上，保留顯示用編號 |
| aired | 有效日期、舊式日期時間或 RFC3339；保留原表示，不補時區 |
| showTitle | 非空白文字，最多 1024 UTF-8 位元組 |

來源值使用 `episode-details-v1`。共用電影的 28 個欄位加單集六欄，合計 34 欄；不包含影集計數及播出文字。全域鎖涵蓋這 34 欄，缺值欄位只記錄鎖，不虛構資料。人工 `null` 表示清除，明確值優先於後續 NFO；只改鎖旗標會保留值的來源。

人工 API 的欄位聯集為 30 個 facts、16 種值變體；含文字欄位的回報上限為 39。這是各媒體種類的聯集，單集 NFO 實際支援 34 欄。

## 一致性與遷移

重複欄位、衝突別名、非法編號／日期、過長文字、錯誤根元素及多筆內容均拒絕。讀取結果擁有自己的可選編號副本，來源重新檢查可辨識原檔變動。保存不改動影片、NFO 或圖片，也不建立父影集。

第 38 版增量 SQL 擴充值、來源與獨立鎖約束。已有單集值、人工清除、鎖或來源證據時拒絕降版；第 1–37 版共 74 份已發布 SQL 保持原樣。
