# 合併規則的共同最終復核

## 啟動與期限

`BeginFamilyIgnoreVerification` 要求基線分類完整且沒有未知項目，並核對基線版本、清單世代、兩份來源清單與根目錄覆蓋。它在同一交易凍結兩份來源清單，建立三份復核進度：自有規則 proof、舊格式最近來源查詢、舊格式基線缺失邊界查詢。

三份進度使用相同 generation 與固定 deadline。期限取租約、啟動後 120 秒、同代既有舊格式復核期限的最小值。同代重試不清除進度，也不續期；新租約世代從第一頁重做並清除封存。過期的獨立舊格式期限不能藉共同啟動延長，失敗時不留下部分進度或凍結狀態。

## 分頁與封存

新增合併模式的自有 proof Next／Commit，重用既有分頁、完整欄位比對、摘要及 EOF 計數邏輯；舊入口仍拒絕合併模式。舊格式兩路使用既有獨立 token。自有頁提交前後都驗證三份進度的共同期限；來源改變保留失效標記而不前進游標。

`SealFamilyIgnoreVerification` 同時要求：

- 三路皆完成 EOF，已驗證數量各自等於來源清單中的 proof、來源查詢和基線查詢總數。
- 兩份來源清單已凍結且未失效。
- 三份進度屬於同一有效租約世代，期限相同且未到期。

封存期限不超過共同 deadline 或 30 秒，重試不能延長。最後資料庫寫入後再次檢查租約、清單世代及共同期限；寫入延遲造成到期時，整筆封存回滾。

## 驗證

原生掃描、規則子程序、分類保存之後，實際重讀三路來源，再逐頁提交到 EOF。只完成自有 proof 或尚未完成缺失邊界復核時均拒絕封存；三路完成後通過。此非 race 驗收耗時 15.655 秒，沒有略過，也沒有存活子程序。

專項 PostgreSQL race 8 項通過、零失敗、零略過，28.234 秒。涵蓋同代重試、換代重啟、既有期限、缺進度、來源改變、期限不同、三路計數、未知分類拒絕及延遲寫入回滾。先前分頁與既有復核回歸 11 項通過，31.388 秒。

本段沿用 schema18，沒有修改已發布遷移。合併模式的最終發布、正式 worker 與公開入口仍待接線，封存不等於已發布清單；G22 與第 3 階段尚未完成。

完整 PostgreSQL race 回歸：235 項頂層測試通過，零失敗、零略過，309.436 秒；測試期間原始碼不變。證據為本機忽略目錄 `.testdata/inventory-family-verification-full-postgres-summary.json`。Windows domain/scan/architecture 全套、全專案 vet、三命令 build 通過。
