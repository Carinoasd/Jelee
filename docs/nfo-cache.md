# NFO 验证快取契约（3C3B）

本段提供按库策略、持久验证摘要与扫描检查点的数据库契约。3C3C 的运行时 worker、库级 API/CLI 和图片比较见[工作流程](nfo-worker.md)，实际执行次数见[验证报告](nfo-worker-verification.md)。单文件 CLI 继续使用已有只读来源解析。

## 保存什么

按库模式为 `off` 或 `read-only`，初始为 `off`。模式和媒体根映射的变化递增独立的 NFO generation；仅修改 NFO 模式不会使影片 probe cache 失效。

快取键包含库、根、相对路径、size、纳秒 mtime、完整内容 SHA-256、指纹版本、解析器版本、摘要 schema 版本、输入上限以及来源 generation。完整读取与 hash 仍然必要，命中只省略 XML 解析。文件系统身份检查的限制见[来源说明](nfo-incremental-plan.md#必须公开的并发限制)。

快取只保存验证摘要：有效/无效、固定编码与根类别、条目数、warning/error 数，以及最多 64 个固定代码的问题。问题列表是按来源顺序保留的前缀，总数和截断标记单独保存。摘要最多 16 KiB；Go JSON 与 PostgreSQL JSONB 的实际文本长度均检查。

转接层将兼容 XML 包装根统一映射为 `wrapper`；核心摘要不保存旧品牌根名。未知或带命名空间的未知根仍为 `unknown`，并保留固定告警。

原始 XML、title、plot、人物、第三方 ID、图片 URL、任意字段值和任意错误消息不进入摘要。此摘要不能用于 Catalog 导入、字段锁决策或 metadata 合并。以后改变摘要投影或解析语义须更新对应版本，不能把旧摘要解释成新的 metadata。

XML/编码/结构解析错误可成为短期无效摘要；warning 本身不代表无效。来源变动、无法读取、未取得完整 hash 的超大输入、取消和存储故障不成为 XML 负缓存。未知问题代码属于解析契约错误，不能静默忽略后返回“有效”。

## 容量和保留

| 配置 | 默认值 |
| --- | --- |
| 全局条目/计费字节 | 100,000 / 256 MiB |
| 单库条目/计费字节 | 50,000 / 64 MiB |
| 有配额记录的库数 | 1,024 |
| 有效摘要 TTL | 30 天 |
| 无效摘要 TTL | 15 分钟 |
| 单行计费 | 2,048 字节固定额度 + JSONB 文本字节 |
| 读取页/命中提交批次 | 32 / 16 项 |
| 新解析结果提交 | 每次 1 项 |
| 单次维护删除上限 | 128 项 |
| 策略幂等记录 | 24 小时；全局 4,096、每 actor 64 项 |

计费字节是明确的容量模型，不代表 PostgreSQL 表、索引、WAL 或进程的实际磁盘/RSS 占用。数据库初次设置容量后，其他实例须使用相同配置；不能悄悄覆盖共享配额。

## 阶段与事务

`PrepareNFOPhase` 在保存盘点前冻结模式、NFO generation 与可信解析身份。`read-only` 保存 `waiting`；盘点全部结束后才进入 `running`。恢复不会重新选择版本或 generation。

冻结为 `off` 的工作保存 `aborted / nfo_disabled`，仍可完成普通盘点。扫描途中启用 NFO 不会给此工作增加解析。只有这个原始 off 状态有此例外；开启状态的工作不能靠一般 Abort 取得跳过许可。

运行中沿连续 inventory cursor 处理 NFO。来源读取、完整 hash 与 XML 解析在事务外；快取、配额、进度和检查点在同一短事务内提交。旧 token 返回冲突，调用者重新加载已保存 phase 后继续，避免重复计数。

所有写入重新核对 parent job 的 owner、generation、租约、取消状态和 NFO scope generation。命中也在提交时重新核对身份、状态和 TTL。默认同库仅一个活动 job，故本段复用 parent 租约，不新增每文件 child 租约。

旧解析器的持久 phase 可以加载并中止，但不能继续执行或重新固定版本。旧身份、旧 generation 或过期的 cache 先视为未命中，允许重新解析后替换；匹配当前身份的记录则必须通过严格摘要解码，缺字段、额外字段、null 与不一致计数都返回固定存储错误。

策略操作需要当前有效的管理员会话，包含幂等重放。请求比较库、模式与 expected generation；相同 actor/key 的不同请求返回冲突。同模式不递增 generation；关闭再开启则产生新 generation，不能恢复使用旧代缓存。

## 迁移和回滚

新迁移为 `000006`，已发布 `000001`–`000005` 保持不变。新 binary 只接受 clean schema 6。

回滚前应停止相关 worker，并结束或取消仍活动的 NFO 阶段。down 迁移拒绝会丢失活动意图的状态；不自动修正 dirty migration。回滚会移除本段新增的模式、NFO 摘要、配额与阶段记录，保留此前 Catalog、账户、任务和 probe 数据，也不访问用户原文件。

## 验证范围

本文件描述实现契约；实际执行结果与限制须以该阶段验证报告为准。未接入 worker 前，不把数据库单元/集成测试称为库级解析、暖扫描 Parse=0 或 1,000 文件性能验收。

NFO inventory 页使用 `job_inventory_nfo_page_idx`（仅包含 `kind='nfo'`），按 job/id 游标读取，避免先遍历混合库中所有影片和图片。cache 的全局/单库过期页与 LRU 页分别有对应索引。策略幂等计数最多扫描受限的 4,096 条记录；空库配额维护最多考虑 1,024 个 scope。这些小表上界不能推广为完整媒体库任意查询都已通过性能验收。
