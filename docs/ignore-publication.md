# 忽略掃描的基準保護合併

`FinishIgnoreJob` 是明確的忽略掃描完成入口。它核對有效租約、完整基準分類、根範圍與基準版本，確認 NFO 與影片探測階段完成，並再次查證目錄覆蓋與零跳過。一般 `FinishJob` 與 enabled 任務領取仍受原有守衛保護，實際過濾工作程序尚待接線。

## 發布與人工檢查

同一範圍的缺失比例分母只含舊基準中本輪已觀察項和確認缺失項；被排除項與新增項不會稀釋比例。達到缺失數或比例門檻時保存需要檢查的任務結果，舊基準完全保留。

有 unknown 時可以結束為需要檢查，但不宣稱缺失，也不發布基準。此結果不需要 seal，因為沒有資料獲得發布資格；圖片觀察只計入尚未比較。

其他結果必須持有當前租約世代下未過期的 seal。允許發布時：

1. 在變更基準之前計算圖片統計。
2. 核對本輪庫存加上保留項仍在任務與500,000筆硬上限內。
3. 同一範圍下只保留明確分類為 excluded 的舊項，其屬性、範圍與觀察版本原樣保留。
4. 推進庫的基準版本，再寫入本輪已觀察項，標記新的觀察版本。
5. 在同一交易內寫入任務結果、稽核與歷史清理，最後再次核對租約、範圍和 seal。

舊範圍不可比而本輪完整時，重新建立當前範圍基準，不保留舊排除項，也不宣稱舊項缺失。任何交易錯誤或期限失效，都會回滾基準、版本、圖片統計和任務結果。

## 圖片統計

同一範圍內，只有確認 included_missing 的舊圖片會因未觀察到而計入缺失；excluded 圖片保留但不算缺失。舊圖片在相同路徑改成影片時，計入圖片缺失，卻仍是已觀察到的一般檔案。變更、新增、相同的圖片依既有屬性規則比較。

舊範圍不可比或當前有 unknown 時，所有當前圖片都列為尚未比較。清除任務歷史不影響保留的基準；後續關閉忽略規則的掃描會重新比較這些項目，不繼承過期排除決定。

## 驗證邊界

本階段不新增 schema，也不修改既有遷移。這是資料庫發布合同，尚未驗收原生來源重新讀取或過濾枚舉。完整 PostgreSQL race 168 項頂層測試通過、零跳過；Linux 全模組 vet 與三個程式建置通過，來源雜湊不變。Windows 領域與 PostgreSQL 套件測試、vet 通過；Windows 未配置資料庫，整合證據來自 Linux。本輪未重跑真實媒體驗收。[詳細證據](evidence/ignore-publication.json)。
