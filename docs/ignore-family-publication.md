# 合併規則的基線發布

`FinishFamilyIgnoreJob` 將合併分類接入既有發布交易。自有模式與合併模式共用發布核心，各自使用正確的分類表與來源守衛；舊模式入口仍拒絕合併模式。

## 發布條件

分類必須完整，版本與清單世代必須一致。沒有未知項目時，發布前後都檢查三路復核的共同期限、租約世代、完成狀態、計數，以及兩份凍結且未失效的來源清單與有效封存。NFO／probe 階段、掃描覆蓋、略過數、缺失門檻、租約及最後清單世代檢查沿用既有流程。

未知分類會得到待確認結果，不替換基線，也不宣稱已確認的缺失數。缺失比例的分母排除被忽略項目；超過門檻時保留舊基線。不可比較的舊範圍可依既有規則重新建立基線，不把舊範圍直接算成缺失。

## 歷史保留與圖片統計

可發布時，只移除需要替換的舊基線；被合併規則排除的項目保留原屬性、世代與觀察版本。新清單與保留的排除項目合計不得超過 MaxEntries 或 50 萬筆上限。圖片缺失數使用合併分類表，避免漏掉真正缺失圖片或誤計被忽略圖片。

分類表名稱由程式內兩個固定值選取，不接受外部 SQL 識別字。終態寫入後再次驗證封存；寫入延遲導致過期時，基線、圖片計數、任務狀態與稽核資料一起回滾。
