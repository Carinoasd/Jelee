# 只读文件清单扫描

`internal/adapter/scan` 每次枚举一个目录的直接子项，输出普通文件元数据与待扫描子目录。目录递归、任务租约、取消请求、数据库批次检查点和重试由任务层处理。

扫描器不读取媒体内容，不做哈希、媒体探测、NFO 解析或外部进程调用，不修改源文件，也不把观察结果转换为可播放目录条目。测试中的哈希比较用于确认原文未变，不是扫描流程的一部分。

## API 与批次契约

```go
scanner := scan.New()
err := scan.ValidateRoot(ctx, absoluteRoot)
err = scanner.ScanDirectory(ctx, domain.ScanDirectory{
    RootID:   rootID,
    RootPath: absoluteRoot,
    Path:     ".",
}, func(batch domain.ScanBatch) error {
    return repository.SaveScanBatch(ctx, lease, directory, batch)
})
```

- `ValidateRoot` 只确认管理员配置的绝对目录可以打开，不创建目录、不枚举内容，也不在注册后持续持有目录 handle。
- `Path == "."` 表示根目录；其他路径都相对该根，并用 `/` 分隔。
- 每次调用 `ReadDir(128)`。一个回调中的文件与子目录**合计**最多 128 项，不把整个目录读入内存后再切分。
- 所有文件与子目录都是当前目录的直接子项，输出完整根相对路径。顺序取决于文件系统，不保证排序。
- `InventoryEntry` 仅包含 `RootID`、`Path`、`Kind`、`Size` 和 `ModifiedUnixNano`；扫描器不生成 ID。
- 最后发送一个空的 `Done=true` 批次，其中 `Skipped` 是本目录跳过项总数。此前所有批次的 `Skipped` 均为零。空目录同样发送一次完成批次。
- 回调同步执行，失败即停止读取并原样返回错误，包括数据库错误、租约失效与取消。回调属于内部任务层，公开接口需按固定错误代码映射，不能直接输出任意底层错误文本。

扫描器没有后台队列或共享可变状态。单次调用的工作集随批次与路径深度有界；同时扫描多少目录由调用方限制。

## 路径与资源边界

根相对路径必须是有效 UTF-8、规范且本地的路径，不能含空组件、`.` / `..` 中间组件、绝对路径、反斜线、冒号或 Unicode 控制字符（包括 NUL、换行和制表符）。保留名称中的普通空格和其他 Unicode 字节，不做重命名或归一化。

路径最多 1024 字节、128 个组件；根 `.` 的深度为零。文件名也占一层，因此位于第 128 层目录中的子项会超过深度上限。超过长度或深度时返回 `ErrScanLimit`，不会把该目录标记完成。不能安全表示的子项名称，例如无效 UTF-8、控制字符、反斜线或冒号，计入跳过项。

元数据只接受普通文件和普通目录。符号链接、FIFO、socket、设备及不规则文件系统项均跳过；目录链接不进入待扫描目录列表。负文件大小或不能以 Unix 纳秒表示的时间值也按限制错误终止。

`video`、`nfo`、`image`、`other` 是按大小写不敏感的扩展名分类。常见视频容器、`.nfo` 与图片资产扩展名有对应类别，其余为 `other`；`.iso` 目前归 `other`。这只是清单分类，不能据此判定真实格式或文件可播放。

## 文件系统边界与符号链接

实现只在 Linux 和 Windows 启用；其他操作系统返回 `ErrScanUnavailable`，避免把未验证平台的行为宣称为安全边界。

扫描先用 `os.OpenRoot` 固定配置目录，再通过同一 Root 以只读方式打开待扫描目录。路径中可见的每级符号链接都会被拒绝，打开前后还会检查目录身份；随后读取固定的目录 handle。Linux 额外使用 `O_DIRECTORY | O_NONBLOCK`，避免把竞争中替换的 FIFO 当作普通读取目标。

`os.Root` 对根相对路径提供阻止父目录与符号链接逃逸的边界；它允许指向根内的相对链接。官方说明见 [Root API](https://pkg.go.dev/os#Root)与 [Go 文件遍历防护说明](https://go.dev/blog/osroot)。本实现使用的 Go 1.27.1 在通过 Root 打开的 Linux 目录上采用 handle-relative `lstat` 元数据；Windows 目录枚举从目录 handle 取得子项信息。扫描器不使用拼接的绝对文件名补查子项。

打开前后检查不是一个原子的“绝不经过内部符号链接”操作。在极短竞争窗口里，目录可能被换成指向同一目录对象的内部链接，再被换回；不能声称这种内部链接一定被察觉。根外符号链接仍由 Root 的路径解析拒绝。并发改名、替换或删除也意味着这不是目录的原子快照；例如系统目录枚举期间消失的项可能不再出现。出现扫描错误时不发送完成批次，最终缺失处理由任务层决定。

任务层只在扫描成功、没有跳过项且缺失量未触发复核阈值时替换已接受的清单基准。失败、取消、有跳过项或大量缺失需要复核时保留旧基准；连续重扫仍会显示同一缺失差异。当前没有确认复核并接受新基准的接口，重复扫描本身不会确认这些差异。

配置根及其祖先属于受信任的运维边界。根叶节点的可见符号链接会被拒绝；配置根祖先的正常系统链接可能由 `OpenRoot` 解析。每次扫描会重新打开配置路径，因此本模块没有跨任务持久固定根 inode 的承诺。已经打开的目录随其 handle 指向对象，改名后也不会改为按原绝对路径重新访问另一个对象。

Root 不能禁止根内硬链接、挂载点或 Linux bind mount。指向同一 inode 的硬链接仍被观察为普通文件；扫描只记录元数据，不读取或修改其内容。它也不是对本机管理员修改挂载与文件系统的隔离机制。这些限制与 [Go Root 的边界说明](https://pkg.go.dev/os#Root)一致。

## 取消与错误

扫描在打开、路径检查、读取、处理子项和回调边界检查上下文。取消时通过 `context.AfterFunc` 关闭已打开的目录文件，以释放可以通过关闭结束的阻塞读取；结束前等待关闭回调完成，不保留脱离任务的读取 goroutine。任务层回调也必须响应同一个上下文。

网络文件系统的 `OpenRoot`、打开、stat 或目录读取可能阻塞在内核中，关闭文件不保证立即中断所有此类调用。因此任务期限不是任意挂载故障下的硬退出保证；深目录还有逐级身份检查的额外开销，最高深度固定为 128。普通目录枚举也可能触发文件系统自身的访问时间更新，代码本身不执行写入、修改时间或权限操作。

扫描器自身的错误只有 `ErrScanUnavailable`、`ErrScanIO`、`ErrScanLimit` 或上下文取消/超时，不带本地路径与底层异常信息。内部回调的错误按前述约定原样回传，由任务层安全分类。

## 测试与已知环境限制

测试覆盖真实 1000 个文件和 17 个子目录、128 项批次上限、文件大小与时间、Unicode/空格、原文件哈希不变、只扫描直接子层、1024 字节和 128 层边界、符号链接与硬链接、取消阻塞读取、回调失败传播，以及只在完成时提交跳过总数。

Linux 还有目录与根外符号链接并发替换测试，要求实际发生交换才算完成。测试环境不支持相应文件系统操作时明确跳过：WSL DrvFS 会替换非法 UTF-8 名称字节、不支持 FIFO 创建，且无法依靠 chmod 证明内容不可读，因此该环境的三个跳过项不能记作通过。

另以固定 Go 1.27.1 构建静态 race 测试程序，在固定构建镜像内的原生 Linux tmpfs 重跑全部扫描测试，所有测试通过且没有跳过项，包含上述三个真实文件系统用例及 351 次目录与符号链接交换。容器使用 UID/GID 65532、只读根文件系统、移除全部 capabilities、禁止新增权限与网络；测试数据仅位于容器项目目录 `/project/.testdata`。完整输出、源码与测试程序 SHA256 见 [原生 Linux 扫描证据](evidence/jobs-scan-linux-native.txt)。
