# 忽略規則的一萬檔規模基線

正式 `FamilyIgnoreScanner`、規則輔助程序、worker 與 PostgreSQL 跑三輪實際檔案掃描。總數一萬包含 9,998 個合成影片及兩個規則檔；每個目錄最多一千個影片。第一輪允許全部影片，第二輪修改傳統規則排除一半，第三輪保持規則不變並清理舊快照。

| 輪次 | 秒 | 本次觀察 | 保留歷史 | 底層快照列 | 輔助程序啟動 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 首次 | 5.04 | 10,000 | 0 | 10,000 | 91 |
| 排除一半 | 70.77 | 5,001 | 4,999 | 20,000 | 10,089 |
| 保持規則／清理 | 68.51 | 5,001 | 4,999 | 20,000 | 10,089 |

三輪都 attempts=1，批次最多 128。保留歷史仍使用首次觀察版號，本次觀察才取得新版號；驗證可見基準共一萬筆，第三輪不持續累積舊列，原始媒體抽樣內容不變。

GOMAXPROCS=2、GOMEMLIMIT=512MiB、單 worker，使用原生 ext4 及獨立 PostgreSQL 16.15 磁碟實例。取樣 heap 峰值約 3.41 MiB，worker 所在程序 RSS 峰值約 25.05 MiB；不包含輔助子程序與 PostgreSQL 的合計記憶體。GOMAXPROCS 不等於硬體 CPU 配額。

重掃的輔助程序啟動由 91 增為 10,089 次。程式目前對每筆未觀察歷史，逐層重新判斷規則；每筆含父目錄與檔案兩次比對。此基線先保留實際成本，後續檢查是否能在有界批次內合併比對，同時保留來源身分與前後重驗。

本段只新增 opt-in 規模測試與證據，schema44 產品程式未變。十萬／五十萬忽略模式、單一大目錄、圖片／probe 混合負載、容器 OOM 及真實 24h 尚未驗收；三輪也不足以證明長期記憶體穩態。

[機器可讀證據](evidence/ignore-scale-baseline.json)。測試須指定專用資料庫、原生 ext4 臨時目錄、唯一輸出目錄、`JELEE_RUN_IGNORE_SCALE=true` 與 `JELEE_SCAN_SCALE_FILES`；固定工具鏈執行 `go test -count=1 -run '^TestIgnoreScanScale$' ./internal/adapter/postgres`。沒有 opt-in 時明確略過。
