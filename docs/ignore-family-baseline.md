# 合併規則的基線分類

本段實作 `EvaluateFamilyIgnoreBaseline`，schema 維持 17，公開合併模式仍未開放。

## 判定順序

對舊清單中尚未觀察到的檔案，先依序判定每個祖先目錄，再判定檔案。自有規則明確 Include/Exclude 優先；只有 Unmatched 才查固定舊格式來源。任一祖先被排除即停止，後代的包含規則不能使該子樹重新進入掃描。

舊格式目錄查詢包含該目錄自己的來源；自有格式只能使用祖先來源決定是否進入目錄。結果保留 family、reason、來源目錄、行號與實際命中的祖先路徑。空來源／全無效來源使用行號 0，規則命中使用有效行號。Unknown 原因沿用固定代碼，來源錯誤由呼叫端處理，不能改為 included_missing。

## 證據與限制

每次自有觀察與舊格式匹配都使用既有原生安全讀取。分類內重複自有 proof 必須相同，舊格式 checked proof 必須相容；兩種來源的目錄身份、父身份與首個缺失邊界必須一致。缺失目錄不製造更深層身份。自有 proof 去重；舊格式保留每次查詢邊界供後續保存與復核。

整次分類與掃描共用兩個名額及 30 秒期限，路径深度受既有上限約束，期限傳到子程序。失敗返回空結果，取消釋放名額。

分類結果仍是暫定值。included_missing 必須綁定資料庫尚未觀察到的基線頁、完整掃描覆蓋、來源保存與最後復核，才有資格參與缺失統計。本段尚未接資料庫分類保存、發布或正式 worker；不能據此宣稱 G22 完成。

## 驗證

- Windows scan/domain/architecture 全套：1.688 / 0.174 / 0.159 秒通過；全專案 vet、三命令 build 通過。
- Linux 原生檔案系統 race：scan/domain/architecture 1.176 / 1.051 / 1.095 秒通過。
- Linux 真實受限 helper：TestFamilyBaselineNativeHelper 0.022 秒通過；Windows 同測試包含在 scan 全套。測試涵蓋自有優先、祖先空來源排除、全無效來源、缺失父目錄及根來源檔案規則；結束時無存活子程序。CI 已加入非 race 執行步驟。
- 額外測試驗證父目錄排除不可被後代包含復活、custom/legacy 來源改變、兩名額耗盡、取消與期限傳遞、來源路徑關係和私有資料遮蔽。
