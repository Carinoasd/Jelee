# 唯讀 NFO 的項目欄位套用

管理員可使用 `POST /api/v1/items/{id}/metadata/nfo`，提供目前 `expectedRevision` 與明確 `confirmed: true`。需要帳號功能，項目所屬庫需啟用唯讀 NFO；套用入口不依賴 TMDB 金鑰或掃描工作開關。NFO 庫設定仍使用原有設定流程。

## 來源與讀取

來源由資料庫的項目、唯一媒體來源及所屬庫根目錄決定。優先同名相鄰 `.nfo`，例如 `dir/Film.mkv` 對應 `dir/Film.nfo`，其次為電影的 `movie.nfo` 或劇集的 `tvshow.nfo`；[來源選擇](nfo-item-selection.md)採檔名大小寫比對與歧義拒絕。來源不存在、多媒體來源歧義、不安全相對路徑、非絕對根目錄或不支援種類時拒絕，不選第一筆。HTTP 不接受路徑、欄位值、雜湊或來源宣告。

沿用安全根目錄讀取與不可變原始位元組解析，抽取標題、原名、簡介及日期。只接受單一、種類相符的 movie／tvshow 主項目。未知命名空間、包裝／多項目、重複單值欄位、非法 XML／日期、過大欄位及沒有可套用文字時拒絕，失敗不回傳部分資料。文字仍需介面跳脫；不下載 NFO 內的圖片或網址。

先以短交易驗權限、版本及来源，再於交易外讀取、解析並完整重讀。兩次觀察的完整雜湊、檔案戳、解析身分、欄位及鎖意圖須一致。最終短交易再驗有效管理員 session、項目版本、種類、媒體／根目錄／路徑及 NFO 世代。

這些觀察點不是檔案系統原子快照；最後觀察之後仍可能變動。阻塞檔案系統的 open／stat 也不是硬性可取消操作。不可把這些限制描述成已排除所有檔案競態。

## 優先序與鎖

- 人工來源優先，包括明確空值；人工鎖與已保存的 NFO 鎖均保護欄位。
- NFO 可取代既有或 TMDB 欄位。缺值保留，不自動清空欄位。
- `LockData` 保護本次套用的欄位；`LockedFields` 的 Name／OriginalTitle／Overview／PremiereDate 對應目前四欄。其他欄位尚未套用。
- `locked` 是人工鎖旗標；`nfoOrigin.locked` 是 NFO 鎖意圖。只改人工鎖保留 NFO 來源與鎖；明確人工修改值可接管已鎖欄位並清除 NFO 來源，後續仍受人工來源保護。
- 即使後來關閉 NFO 讀取，已保存的 NFO 來源仍優先於 TMDB。清除外部來源另待正式功能，設定關閉不代表放棄已保存來源。

欄位、實際目錄標題、版本及前後稽核在同交易更新；SQL 中途失敗全部回滾。接受的確認即使全部略過，仍推進版本與記錄結果。HomeVideo 接受至少一個 movie 欄位才改為 Movie。

## 來源保存與遷移

`nfoOrigin` 保存媒體來源／根目錄 ID、NFO 世代、完整 SHA256、解析身分摘要、欄位投影版本、讀取時間及 NFO 鎖。API、稽核與一般格式化不包含根目錄或相對路徑。

第 23 版新增受 SQL 約束的 NFO 來源。NFO 必須提供完整且正確的來源，其他來源不能攜带 NFO 來源。保留任何 NFO 來源時拒絕降版；全部人工接管並清除來源後可降回 22。原 001–022 遷移保持。來源 ID 是歷史觀察的識別，不表示當前檔案仍存在；每次套用仍需重新解決來源。

## 驗證與待接續

真安全檔案、應用、HTTP 與 PostgreSQL 驗證套用、人工接管、空值／鎖、原檔保持、過期版本、非法 XML、檔案變更及 NFO 世代變更，失敗不留下更新或稽核。另有 SQL 中途失敗回滾、升降版與來源約束，以及正式資料庫路徑的來源優先序負例。詳見[來源與執行證據](evidence/nfo-item-metadata.json)。

目前是明確確認的項目套用。唯讀庫與 TMDB 的同交易融合已接上正式入口，詳見[同次融合](nfo-tmdb-fusion.md)。原始 inventory／worker 與影集階層匯入、季／集欄位、其他 NFO 欄位、清除外部元資料、前端及完整效能驗收仍未完成。此段不寫入原 NFO、媒體或圖片，不代表全案或 G14 全部完成。
