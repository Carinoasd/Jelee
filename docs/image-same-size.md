# 同尺寸圖片不再配置完整副本

G42.6 的同尺寸缺口已修正：不需要縮小時，JPEG 的 Gray／YCbCr 直接編碼；PNG 在本次請求獨占的解碼緩衝內合成白底，再以共用像素的標準圖片型別編碼。原媒體、原圖與暫存原圖不會被修改。真正縮小的路徑沿用既有縮放器。

PNG 的 RGBA／NRGBA、16-bit RGBA／NRGBA、Gray／Gray16 及 Paletted 均有明確處理。16-bit 圖片逐列由左至右轉為 8-bit，寫入落在已讀取的區段，保留原始 stride；palette 最多轉換256個顏色。沒有另一張完整像素緩衝，也沒有隨像素數增加的色彩介面配置。函式只接受已驗證的解碼型別，每列檢查取消；不可用於共享圖片。

既有並發、每圖配置估算、來源／輸出限制與快取預算保持。估算仍保留原輸出 RGBA 餘量，不因這項修正放寬可接受尺寸。Gray／YCbCr 直接編碼省去 RGB 往返，JPEG bytes 可能改變；強 ETag 仍根據實際輸出計算。

## 驗證

實際 640×960 冷 JPEG 請求，以單筆快取與交替品質避免暖命中，修前每筆配置 **3,758,080 bytes**，超過事先指定的2 MiB回歸上限；修後為 **1,282,375 bytes**。第二張RGBA單獨就需2,457,600 bytes，因此這項檢查能抓到原缺口。這是配置量回歸，不是 RSS 或吞吐量測。

| Windows HTTP 圖片 | 44 | 0 |

唯一 Windows 略過為大小寫不同的同目錄檔案歧義，Linux已覆蓋。測試另核對共享像素、非零矩形／含padding的stride、白底標準draw對照、alpha邊界、逐列取消、真PNG輸出及原檔保持；既有progressive JPEG、PNG16及Adam7回歸均通過。Tagged vet、格式與三個正式命令建置通過，922份量測來源保持。[完整來源與結果](evidence/image-same-size.json)。

草稿測試初次未指定尺寸，套用預設640方框後在benchmark內中止，結果回傳零配置。這個結果不算通過證據；已改用明確640×960，兩個配置測試都拒絕零次或零bytes量測，再取得上述真實紅綠結果。

本項完成G42.6的配置、尺寸預檢與避免完整副本要求。其他圖片角色、格式與來源仍依G40接續；[十萬圖片RSS／GC](image-memory.md)證據屬前一提交的縮小路徑，本輪沒有重跑；24小時穩態仍待執行。
