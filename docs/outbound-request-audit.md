## 盤點當時的實際接線

| 範圍 | 來源觀察 | 後續處理 |
| --- | --- | --- |
| Go 服務 | 掃描範圍內，internal 正式來源沒有匹配 HTTP 客戶端建立／送出或 DialContext | 防護須與真正的抓取能力一起接入，再驗證正式呼叫路徑 |
| Go 管理 CLI | jobs 與 NFO 控制面兩檔共 6 行匹配；明確管理目標，預設環回；HTTP 僅接受環回字面地址；拒絕重定向、關閉環境代理、固定安全錯誤 | 保持本機管理能力；不能套用服務端抓取的「禁止環回」規則 |
| 舊服務共用客戶端 | 34 個正式檔案共 43 行 CreateClient 匹配，涵蓋刮削圖片、一般圖片下載、外部影音／字幕、外掛套件及保留中的直播來源 | 依能力逐項遷移／裁剪，追蹤 URL 的信任来源，不以修改一個 factory 代表全部完成 |
| 舊服務傳輸層 | 2 個直接建立的 handler；一條採自訂 hostname 連線，另一條沒有該 callback | 目前可見接線沒有 IP 分類、DNS 結果固定或逐次重定向檢查 |
| 刮削 SDK | 1 行直接建立 TMDB SDK；本地版本鎖定 3.0.0，建構未注入共用 HTTP 客戶端 | SDK 流量不能從共用 factory 的修改推定受保護；仍需查 SDK 接口或改用受控傳輸 |

來源角色、路徑對照見[既有來源索引](branding-rename-map.md)，逐檔 SHA-256 與統計見[證據](evidence/outbound-request-audit.json)。hostname 連線函式把 DNS endpoint 交給 socket；查到這個 callback 不等於已有 DNS 重綁定防護。

## 盤點範圍與限制

以基底提交的 git ls-files，檢查 233 個 Go 與 1,919 個 C# 正式來源；排除 tests/、tools/、_test.go 與 /testdata/。使用建立／呼叫相關字串比對，再閱讀上表的代表性接線。行數是文字匹配數，不是請求數，也不是獨立客戶端數。

此盤點沒有解析所有 alias、反射、動態載入外掛或第三方依賴源码，不能證明全案只存在這些出站方式。新 Go Webhook、遠端 NFO、TMDB 與遠端圖片能力仍需自己的正式入口與覆蓋證據；現有本機 NFO／圖片工作不得誤報為遠端抓取完成。
