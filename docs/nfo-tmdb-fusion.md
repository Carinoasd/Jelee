# 唯讀 NFO 與 TMDB 同次套用

本頁保留該階段的實作與驗證；後續第24版的三態保存及可信缺失／損壞回退，見[最新回退契約](nfo-tmdb-fallback.md)。

管理員確認 `POST /api/v1/items/{id}/metadata/tmdb` 時，唯讀 NFO 庫可在一次最終交易中合併可信 NFO 與 TMDB。沿用第 23 版資料結構，沒有新增遷移。

## 處理流程

先驗項目、權限、版本與種類，從資料庫解析唯一媒體來源及庫根目錄，按[來源選擇](nfo-item-selection.md)讀取同名或慣用檔名 NFO。TMDB 查詢與語言回退在資料庫交易外執行；供應商完成後，完整重讀 NFO，比對位元組雜湊、檔案戳、解析身分、欄位與鎖意圖。

最終短交易重驗管理員 session、項目版本、NFO 世代、種類及全部來源範圍。先套用 NFO，再以交易內的合併結果判斷 TMDB 欄位。人工來源（包括明確空值）、人工鎖與已保存 NFO 鎖均保護欄位；NFO 優先於 TMDB，供應商缺值不清空。簡介回退保留該簡介自己的來源語言及時間。

欄位、來源、目錄標題、種類、版本及稽核一起提交。接受一次確認只推進一次版本、記錄一筆 `item.tmdb_metadata_applied` 稽核；即使全部略過也記錄結果。HomeVideo 只有接受至少一個電影欄位時才改為 Movie。任一 SQL 或稽核失敗皆回滾兩個來源的修改。

## 回應與衝突

頂層 `applied` 列出任一來源實際套用的唯一欄位；`skipped` 只列出兩個來源都沒有套用的欄位。融合回應另有 `nfo`、`tmdb` 報告，分別列出各來源的結果，例如 NFO 已套用日期、TMDB 因 NFO 優先而略過日期。應用複製報告陣列與欄位來源，避免呼叫者共用可變狀態。

兩次觀察間 NFO 改變、等待期間人工修改、世代或根目錄／媒體來源改變，回傳 409。缺少可信來源、歧義、非法 NFO、缺讀者／融合儲存介面或供應商失敗仍拒絕；不留下已提交的 NFO 半份更新。取消也不提交。NFO 關閉的庫沿原 TMDB 路徑，已保存的 NFO 來源仍受保護。

## 驗證與範圍

正式 TCP HTTP、應用、安全 NFO 讀者、受控 TLS 供應商及 PostgreSQL 驗證混合來源、人工空值、NFO 鎖、一次版本／稽核、HomeVideo 分類、變檔、人工修改、世代／根目錄衝突、429 重試、取消及非法供應商回應。供應商等待期間的另一個 HTTP 人工修改可以完成，證明網路等待沒有持有項目鎖。

資料庫另驗全略過結果、來源變更、撤銷 session、供應商欄位與稽核 SQL 失敗的完整回滾。刻意停用正式 NFO 優先序時，完整 HTTP／TLS／NFO／PostgreSQL 測試會因覆蓋 NFO 日期失敗；隨後逐位元復原並重跑。另保留 100 電影／20 劇集合成搜尋、確認及寫入矩陣。完整數字見[執行證據](evidence/nfo-tmdb-fusion.json)。

目前仍只有四個文字欄位、唯一可信媒體來源的同名／慣用 NFO 檔名及單一 movie／tvshow 根項目。缺 NFO 的安全回退、季／集及多項目來源選擇、實際媒體匯入、worker、劇集階層、其他欄位、read-write 無損回寫、清除外部資料及前端尚未完成。

兩次觀察不提供檔案系統原子快照；最後觀察後仍可能變動，阻塞 open／stat 也不是硬性可取消。原 NFO、媒體及圖片均保持。全量品牌與 ABI 仍有失敗，G14／G39 與全案仍未完成。
