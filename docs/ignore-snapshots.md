# 忽略規則的分批快照發布

schema44 將 `.jeleeignore` 及傳統忽略規則的歷史合併接上分批快照。正式 worker 完成掃描、比對與媒體子階段後，先準備不可見資料，再重新驗證規則來源及取得短效封印，最後同交易發布基準與任務終態。

## 批次與保留資料

- 本次觀察列每批最多 128 筆，使用新的基準版號。
- 被忽略的歷史列只從相同範圍的前一快照複製，保留原屬性、根世代及觀察版號。
- 歷史游標先讀最多 128 筆原始決策，再篩選被忽略的列；即使一頁沒有命中，也會推進游標，不為湊滿命中而搜尋整份剩餘歷史。
- 游標、計數與資料同交易提交；新租約持有者可續跑，舊持有者不能寫入。
- 沿用每批最多 512 筆的舊快照清理，保留目前基準及本次準備資料。準備完成以前，使用者仍讀到完整舊基準。

準備狀態新增忽略模式、預期保留歷史數、已複製數與歷史游標。總列數仍受媒體庫工作上限及五十萬上限約束。資料缺失需要人工確認或來源不明時，不建立可發布快照；範圍重設時，只接受本次觀察，不沿用舊範圍的忽略歷史。

## 發布守衛

每批檢查取消、租約、模式、根世代、基準版號與前一快照；批次末端再驗租約與根世代。發布核對已準備數量、模式及封印，保留原有媒體前置階段檢查，以及交易末端的租約和封印再驗證。交易中封印或租約到期，快照指標、任務終態與統計一起回滾。

工作重啟後仍須重新驗證來源。大量複製位於來源驗證之前，不延長封印期限。內部直接呼叫完成介面、未使用準備介面的既有小型契約，仍保留同步合併路徑。

快照保存衍生清單，不修改原始媒體、NFO、圖片或忽略規則。它不保證整個檔案系統同一瞬間的內容；後續檔案事件仍需再次掃描。

## 圖片缺失統計

新測試使用一萬筆基準、九千五百筆目前觀察及四百五十筆缺失決策。原本的逐列連接在未更新統計時累計讀取 49,890,000 列；更新統計後才恢復。現改用集合比對，區分圖片轉成其他種類、確認缺失及忽略保留，並以有／無 ANALYZE 的實際查詢計畫驗證。

## 資料庫相容

001–043 的八十六份已發布 SQL 保持不變。schema44 升版為既有普通準備列填入空模式與零筆忽略歷史；普通準備可降到 43 再升回並接續。有保留忽略準備狀態時拒絕降版，避免舊程式忽略尚未複製的歷史。

## 驗證與限制

已涵蓋兩種忽略模式、零筆目前觀察、稀疏決策分頁、歷史來源保留、接手續跑、取消、範圍與基準失效、模式錯置、容量上限、晚到封印及租約回滾、遷移往返，以及 worker 在來源驗證前完成準備的順序。

純清單的五十萬檔成績不代表忽略規則的同等規模驗收。忽略歷史的大規模完整 worker、混合負載、容器 OOM 及真實二十四小時穩態仍須另外量測。
