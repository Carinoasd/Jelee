# 持久掃描排程

本段對應 G13.1、G41.6。每個媒體庫至多一份排程，建立時必須明確啟用；未設定排程不會自動扫描。排程保存於 PostgreSQL，與既有 `inventory_scan` 共用佇列、容量、優先權、取消及歷史。

## 管理 API

- `GET /api/v1/libraries/{id}/schedule`：管理員讀取，未建立回傳 404。
- `PUT /api/v1/libraries/{id}/schedule`：建立或替換完整定義。`expectedRevision=0` 建立，其後必須提供目前版號；舊版號回傳 409。每次成功更新加一版、將擁有者設為本次管理員，並重新計算下次時間。

```json
{
  "expectedRevision": 0,
  "enabled": true,
  "timing": {
    "mode": "cron",
    "intervalSeconds": 0,
    "cron": "0 3 * * *",
    "timezone": "Asia/Taipei"
  },
  "probe": false,
  "nfo": false,
  "ignore": {"mode": "", "caseMode": ""}
}
```

固定間隔使用 `mode=interval`、`intervalSeconds=60..31536000`、空 cron。間隔按實際秒數，不隨夏令時間縮短或延長。cron 固定五欄，不接受秒欄、`@every` 或內嵌時區覆寫。時區必填，拒絕 `Local`；產品內嵌 IANA 時區資料，作為主機時區資料不可用時的後備。

cron 使用固定版本 [robfig/cron v3.0.1](https://github.com/robfig/cron/tree/v3.0.1) 的日曆計算：不存在的夏令時間時段跳過，秋季重複時段可觸發兩次，按不同 UTC 時刻區分。找不到未來日期的式子拒絕。

`enabled=false` 清空下次到期，不取消已入庫任務。更新定義會從現在重算；已入庫任務保留原意圖。探測、NFO 及忽略設定保存至每次觸發的任務，不默默降級成純掃描。

手動觸發使用 `POST /api/v1/libraries/{id}/schedule/run`、空 JSON 物件及 `Idempotency-Key`。它按讀取當下的設定建立手動優先任務，不啟用停用中的排程，也不推進下一次到期。

## 觸發與復原

每個實例使用可取消的有界輪詢。每輪最多處理一個到期定義；成功後一秒再查，無工作或錯誤後五秒再查。資料庫使用同樣的帳號鎖 → 任務鎖順序，短交易內選定到期排程、建立任務及推進下次時間。只有持有交易鎖的實例能完成該次觸發；程序退出即釋放鎖，沒有可在交易外延遲發布的持久領導權。

停機錯過多次只補跑一次，下次時間由目前資料庫時間計算。容量不足、同庫忙碌或所需能力不可用時保留原到期時間，至少延後三十秒重試，`lastError=admission_unavailable`。內部資料庫失敗會回滾整筆交易；不會只建立工作卻遺失排程進度。

背景觸發依據已保存的管理員授權意圖，不建立假會話。登出不取消排程；每次觸發檢查擁有者仍為未停權、未刪除的管理員。失效時停用並記錄 `owner_unavailable`，須由有效管理員再次更新才能恢復。

`lastJobId` 可查既有任務詳情與進度；歷史依既有保留政策裁剪，刪除任務時此欄清空。下次到期和重試時間由伺服器產生，外部 JSON 不能指定。每次定義更新有稽核，觸發沿用任務提交稽核。排程不修改原始媒體、NFO 或圖片。

## 範圍與回滾

schema41 是新增遷移；001–040 的八十份 SQL 保持原樣。存在排程定義時拒絕降版，避免靜默丟失設定。

檔案監看已由後續 [schema42](scan-watch.md) 接入。本段不包含任務負載曲線、二十四小時穩態驗收、前端排程編輯器或其他業務任務。仍屬第三階段，不能據此宣稱 G13 全部完成。
